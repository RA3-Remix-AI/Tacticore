# 分层决策实施计划：总指挥 + 经济参谋 + 战术参谋

日期：2026-11-20 · 分支：`rework/beta4` · 状态：待评审

## 1. 目标

把现在“一次模型调用决定所有事”的单层决策，拆成分工清楚、互不打架的三层决策，加一个执行层：

- **总指挥**：判断局势，选胜利路线，分配资源。
- **经济参谋**：决定科技升级、扩张和产能。
- **战术参谋**：决定打还是守，以及进攻、巡逻、骚扰、All-in、兵种需求和协议技能。
- **执行层**：由原生 AI 和固定战法完成具体动作。

最终目标不变：AI 自主决策并赢下对局，支持 1.12 任意地图，玩家可以和 AI 组队或与 AI 对打。

## 2. 现状

| 项目 | 现在的做法 |
| --- | --- |
| 调用方式 | 单个模型，宿主最多每 12 秒（墙钟）请求一次（`integration/macro_host.py` 主循环） |
| 输出 | 一个计划：`macro_actions` 至多 6 个意图，每组至多 1 个；附带 `macro_strategy` 声明（目标、阶段、资源优先级） |
| 有效期 | 计划有效 5–60 秒游戏时间，到期不自动续 |
| 输入 | 一份上下文：经济、己方兵力与建筑、敌方接触组、`battlefield_summary`、`match_state`、持续记忆；上限 16KiB（Native7 独立发展合同为 32KiB） |
| 提示词 | v2（`strategy/native_delegation_prompt_v2.py`），v1 可切回 |
| 记录 | 每局一份 `decisions.jsonl`，每轮一条 |

**现有执行能力（模型能真正下到游戏里的指令）：**

| 类别 | 指令 |
| --- | --- |
| 资源 | `budgeteconomy` / `budgetarmy` / `budgettech`（优先级偏好，三选一） |
| 建造与生产 | `pauseconstruction` / `advanceconstruction`，`pauseproduction` / `advanceproduction` |
| 扩张 | `expand`（原生 AI 选位置） |
| 区域部队 | `deployattack`、`deploydefense`、`regroup`、`withdraw`、`reinforce`、`scout` |
| 原生进攻 | `attackenemy`、`raideconomy`（袭扰经济） |
| 目标偏好 | `focusenemy<id>`（优先攻击某个敌人） |

单层决策的问题：
- 一个提示词同时塞了经济、战术、目标选择，上下文和规则都在膨胀。
- 不同决策需要的反应速度不同（战术要快，科技要稳），却被同一个 12 秒节奏绑在一起。
- 决策记录里分不清一个坏结果是经济判断错了，还是战术判断错了。

## 3. 分层设计

```
            ┌──────────── 共享态势 WorldState（只算一份）────────────┐
            │ 经济 · 己方部队与建筑 · 合法敌情 · 对局状态 · 事件流    │
            └───────┬──────────────────┬──────────────────┬──────────┘
                    ↓                  ↓                  ↓
           总指挥（60–120 秒）   经济参谋（30–60 秒）  战术参谋（10–30 秒）
           路线 · 资源分配       科技 · 扩张 · 产能     部队任务 · 目标 · 兵种需求
           主攻对象 · 跨域决策   协议选点               协议技能偏好
                    │ 方针 Directive ─────→ 两个参谋都必须遵守
                    ↓                  ↓                  ↓
            ┌────────────── 计划合成器 PlanComposer ─────────────────┐
            │ 每个领域只归一层所有 → 合成为一份原生计划 → 校验 → 下发 │
            └──────────────────────────┬──────────────────────────────┘
                                       ↓
                  执行层：原生 AI + 固定战法（建造、选址、开火、走位）
```

### 3.1 总指挥

- **职责**
  - 判断局势，选择胜利路线：速攻、稳健发育、科技压制、All-in、防守反击。
  - 分配资源：经济、军队、科技、储备各占多少。
  - 决定主攻对象，下达跨领域决策，例如 All-in、转型海军、放弃分矿。
- **触发**
  - 定时：每 60–120 秒游戏时间。
  - 事件：开局首次、某个敌人被消灭、基地遭到重大打击、分矿丢失、路线到期。
- **输入**：完整态势的精简摘要、两个参谋最近的执行情况、上一条方针。
- **输出**：方针 Directive（见 4.1）。
- **现有能力映射**：资源分配映射到 `budget*`，主攻对象映射到 `focusenemy<id>`。

### 3.2 经济参谋

- **职责**：科技升级时机、是否扩张、产能目标（工厂和矿车数量）、秘密协议选点。
- **触发**
  - 定时：每 30–60 秒。
  - 事件：资金积压或断流、矿车损失、科技解锁、扩张完成或失败。
- **输入**
  - 经济切片：资金、矿车、建筑、产能、科技。
  - 方针。
  - 战术参谋提出的兵种需求。
- **输出**：经济意图 EconomyIntent（见 4.2）。
- **现有能力映射**：`expand`、`pause/advanceconstruction`、`pause/advanceproduction`。
- **待补能力**：产能目标、科技时机、协议选点、兵种构成执行（见第 6 节）。

### 3.3 战术参谋

- **职责**
  - 决定各部队的任务：进攻、防守、巡逻、骚扰、All-in 执行、撤退。
  - 选择目标。
  - 提出兵种需求，例如缺防空、缺反装甲、需要海军。
  - 设置协议技能的使用偏好。
- **触发**
  - 定时：每 10–30 秒。
  - 事件：发现敌方主力、基地或分矿遭袭、己方集结完成、交战结束、计划到期。
- **输入**：军事切片（己方部队、合法敌情、交战区域）、方针。
- **输出**：战术意图 TacticalIntent（见 4.3）。
- **现有能力映射**：`deployattack`、`deploydefense`、`regroup`、`withdraw`、`reinforce`、`scout`、`attackenemy`、`raideconomy`。
- **待补能力**：巡逻、编组任务、协同战法、协议技能释放（见第 6 节）。

### 3.4 执行层

模型一次调用要几秒，不能做实时操作。下面这些都由执行层完成：
- 具体建造和选址；
- 开火、集火、走位；
- 火力覆盖；
- 海陆空协同的具体动作。

执行层由原生 AI 本身，加上以后补的“固定战法”组成：参数化的战法模板，模型只选模板和参数。

## 4. 合同草案

所有层的输出都只是“意图”，不直接授予执行权限。执行权限仍由计划合成器按能力目录校验。

### 4.1 方针 Directive

```json
{
  "route": "rush|steady_growth|tech_pressure|all_in|defend_counter",
  "resource_split": {"economy": 0.3, "army": 0.5, "tech": 0.1, "reserve": 0.1},
  "primary_enemy": 4,
  "overrides": ["no_expansion"],
  "reasoning": "≤300 字",
  "valid_for_s": 120,
  "review_when": ["enemy_defeated", "base_under_attack", "expansion_lost"]
}
```

- `overrides` 是跨域硬约束，两个参谋必须遵守。例如 All-in 会同时带上 `no_expansion` 和 `no_tech`。

### 4.2 经济意图 EconomyIntent

```json
{
  "expand": "now|hold|null",
  "construction": "advance|pause|null",
  "production": "advance|pause|null",
  "tech_timing": "now|after_expansion|hold|null",
  "capacity_target": {"war_factory": 2, "ore_collector": 6},
  "protocol_pick_preference": ["..."],
  "reasoning": "≤300 字",
  "valid_for_s": 60
}
```

- `capacity_target`、`tech_timing`、`protocol_pick_preference` 在第 1 阶段只记录、不执行，等对应能力补上后再启用。

### 4.3 战术意图 TacticalIntent

```json
{
  "posture": "attack|defend|patrol|harass|all_in|regroup|withdraw|scout",
  "target": {"enemy": 4, "region": "region_x_y|null"},
  "composition_need": ["anti_air", "anti_armor"],
  "doctrine": "air_ground_combined|null",
  "power_usage": "aggressive|save_for_defense|null",
  "reasoning": "≤300 字",
  "valid_for_s": 30
}
```

- `composition_need` 是交给经济参谋的需求，不是生产命令。
- `doctrine` 和 `power_usage` 在第 1 阶段只记录、不执行。

### 4.4 领域归属（防止冲突的核心规则）

每个原生领域只归一层所有，计划合成器按归属取各层最新的有效意图，合成一份原生计划：

| 原生领域 | 归属 | 现有指令 |
| --- | --- | --- |
| 资源预算 | 总指挥 | `budgeteconomy/army/tech` |
| 主攻对象 | 总指挥 | `focusenemy<id>` |
| 扩张 | 经济参谋 | `expand` |
| 建造门 | 经济参谋 | `pause/advanceconstruction` |
| 生产门 | 经济参谋 | `pause/advanceproduction` |
| 军事任务（至多一个） | 战术参谋 | `deploy*`、`regroup`、`withdraw`、`reinforce`、`scout`、`attackenemy`、`raideconomy` |

### 4.5 冲突裁决

1. **方针优先**：参谋意图和方针的 `overrides` 冲突时，由合成器丢弃该意图并记录原因。例如方针禁止扩张，经济参谋却要扩张。
2. **兵种需求走经济参谋**：战术参谋不直接改生产，只提需求；经济参谋在下一轮决定是否满足，并记录满足或拒绝。
3. **跨域决策只能由总指挥下**：例如 All-in、转型海军。参谋发现需要时，通过 `review_when` 事件请总指挥提前重审。
4. **过期即回原生基线**：某层的意图过期且没有新意图时，该领域回到原生 AI 默认行为，不沿用旧意图。

## 5. 共享态势 WorldState

- 由单位数据只算一份，三层各取切片，避免各自重复读取、互相不一致。
- 复用现有上下文构造（经济、`own_forces`、`contact_groups`、`battlefield_summary`、`match_state`）。
- 新增**事件流**：主力接触、基地受袭、矿车损失、集结完成、敌人被消灭、科技解锁。事件可以触发对应层提前决策。
- 每层的提示词只放自己的切片，体积明显小于现在的单一上下文，16KiB 上限不再紧张。
- 只用合法的己方视野信息，这一原则不变。

## 6. 开局：胜负的关键（负责人 2026-11-20 确认）

负责人对对局的判断：
- 大部分对局在前期就决定了胜负。
- 不作弊，扩张速度是固定的，所以初期的电力和矿车博弈最关键。
- 主线是：侦察敌方部署 → 用低成本方式干扰对方矿车 → 自己迅速发展 → 快速攀到 T3 单位 → 中期动态作战。攻势的基础在前期打下。

据此把开局单独作为一个阶段来设计：

| 时段 | 谁决策 | 做什么 |
| --- | --- | --- |
| 开局前（大厅到第 0 秒） | 总指挥 | 按地图、出生位置、对手数量和阵营，选一套开局方案：建造顺序、电力与矿车节奏、侦察路线、骚扰时机、攀 T3 的路线。模型调用发生在开局前，不占用对局时间 |
| 0 – 约 3 分钟 | 开局执行器（规则，不调用模型） | 按方案执行建造顺序和侦察；侦察结果一到，立即触发总指挥修正方案 |
| 约 1 – 5 分钟 | 战术参谋 + 骚扰控制器 | 用低成本单位干扰敌方矿车；控制器实时执行，模型只决定派不派、打谁、什么时候撤 |
| 约 3 分钟起 | 经济参谋 | 盯电力和矿车博弈：补电、补矿车、攀科技的时机；对比敌我矿车数和电力状态 |
| 中期 | 三层正常运转 | 动态作战，T3 出来后由总指挥判断转入进攻 |

开局方案以“开局方案库”的形式维护：每套方案都是可参数化的建造顺序和节奏，模型选方案并调参数，不逐条下建造命令。方案库的效果用评估工具逐套对比。

## 7. 直接控制单位（负责人 2026-11-20 允许）

**原则：模型永远不进实时循环。**模型决定“做什么”，固定的控制器决定“怎么做”：

```
战术参谋（每 10–30 秒，或事件触发，一次调用）
   └─ 选控制器 + 参数，例如：骚扰矿车(单位组, 目标敌人, 血量低于 40% 撤退)
         ↓
控制器（宿主或原生侧，每 0.2–1 秒一轮，纯规则，不调用模型）
   └─ 选目标、走位、集火、撤退；把关键事件（击毁矿车、损失、撤退）汇报给战术参谋
         ↓
游戏命令（移动、攻击、停止）
```

- **token 不随操作频率增长**：模型只在选控制器、改参数时调用一次，控制器每秒几轮的操作不消耗 token。
- **实时性由控制器保证**：模型调用需要几秒，控制器在宿主里每 0.2–1 秒运行一轮，不受模型延迟影响。
- **单位所有权**：被接管的单位要先从原生 AI 手里借出来，否则原生 AI 会马上给它们下新命令；结束后再交还原生 AI。这是最大的技术风险，要最先验证。
- **复用早期成果**：项目早期在 `tactical/` 做过直接控制实验，包括移动、停止、回家、单位借用，以及矿车骚扰组合（`tactical/combo-harass_economy-evidence.json`）。当时没走通的主要原因，是证明要求过重：逐枪伤害归因、单兵租约等，见 `docs/architecture-iteration-plan-20261026.md`。这次按合理强度验证：只确认命令下发成功、单位确实在执行、结束后能交还原生 AI。
- **控制器只做少数高价值的**：先做矿车骚扰和侦察，有收益再做集火、火力覆盖、海陆空协同。

## 8. 执行能力缺口与补齐路线

拆分决策层本身在 Mac 上就能完成。真正难的是补执行能力：要改 Mod 人格、原生组件或直接控制，并在 Windows 实机验证。按负责人对胜负关键的判断重新排序：

| 优先级 | 能力 | 归属 | 实现思路（待在 SDK/实机核实） | 验证方法 |
| --- | --- | --- | --- | --- |
| P0 | 单位借用与交还 | 执行层 | 在早期移动控制器研究基础上，做一套“借出一组单位 → 控制 → 交还原生 AI”的最小可用版本 | 借出期间原生 AI 不再给这些单位下令；交还后原生 AI 恢复使用 |
| P1 | 开局建造顺序与电力/矿车节奏 | 总指挥选方案，开局执行器执行 | 优先用“Mod 标志切换原生建造清单”实现几套方案；做不到再由宿主直接下建造命令 | 电厂、矿场、矿车的出现时间与方案一致；相对基线矿车数领先 |
| P1 | 侦察 | 开局执行器、战术参谋 | 现有 `scout`；需要更早或更准时，用直接控制按路线侦察 | 发现敌方基地和矿区的时间点 |
| P1 | 矿车骚扰控制器 | 战术参谋 | 直接控制一小队低成本单位：找到敌方矿车、集火、危险时撤退；现有 `raideconomy` 作为对照 | 击毁敌方矿车数、骚扰成本与收益比、敌方经济曲线 |
| P1 | 攀 T3 的科技时机 | 经济参谋 | 建造门加科技建筑的推进/暂停标志；必要时直接下建造命令 | 首个 T3 单位出现时间相对基线提前 |
| P2 | 兵种构成偏好（防空、反装甲、海、空） | 经济参谋（满足战术需求） | 标志切换原生部队模板或生产权重 | 对应兵种的生产占比变化 |
| P2 | All-in | 总指挥下令，战术执行 | 军队预算 + 暂停建造 + `attackenemy`，必要时直接控制全军出击 | 出击兵力占比、投入转向 |
| P3 | 秘密协议选点与技能释放 | 经济参谋（选点）、战术参谋（释放） | 查原生 AI 的协议购买清单和技能逻辑，用标志调整；释放时机必要时由控制器执行 | 实际协议与偏好一致；技能使用时机变化 |
| P3 | 巡逻、编组任务 | 战术参谋 | 控制器实现区域巡逻和多支编组 | 部队按任务移动 |
| P4 | 集火、火力覆盖、海陆空协同 | 战术参谋 | 控制器实现，在 P0/P1 控制器稳定后再做 | 交战损失比相对基线的变化 |

**每补一项能力，都必须用评估工具做一次对照实验，确认有收益才保留。**

## 9. 评估方案

**自动连续开局**：Windows 上用 computer use 操作大厅开局，可以挂机连续跑（负责人确认）。把它接入评估流程：开局脚本按配置设置地图、席位、对手和难度 → 启动宿主 → 对局结束后写入结果 → 退出并开下一局。结果直接进 `benchmark/eval/`。

使用 `benchmark/eval/`：

- **对照组**
  - A：纯原生 AI；
  - B：当前单层 v2；
  - C：分层决策。
- **固定条件**：同一地图、同一出生位置、同一对手难度。
- **样本量**：区分 50% 和 70% 的胜率，每组约 90 局；区分 50% 和 60%，每组约 400 局。全部实机跑成本很高，所以：
  - **第一轮先看过程指标**：决策被拒率、意图冲突次数、经济曲线（资金和矿车）、兵力峰值、首次进攻时间、存活时长。每组 10–20 局就能看出明显问题。
  - **开局专项指标**：第 3 分钟和第 5 分钟时的敌我矿车数与电力状态、首次发现敌方基地的时间、骚扰击毁的敌方矿车数、首个 T3 单位出现时间。这些最贴近负责人判断的胜负关键，样本少也灵敏。
  - **对手难度从中等起步**：胜率在 50% 附近时，统计最灵敏；再逐步升到凶残。
  - **胜率结论只在样本足够时下**，报告里写明置信区间。
- **决策记录**：`decisions.jsonl` 每条增加 `layer` 字段（`commander` / `economy` / `tactical` / `composer`），以及合成器的丢弃和裁决记录。复盘页按层分栏显示。

## 11. 成本与风险

- **成本**：负责人确认暂时不考虑成本。默认三层都用最强的模型；战术参谋在交战中可以提高调用频率。调用量估算：一局 15 分钟，总指挥约 10 次、经济参谋约 20 次、战术参谋约 60 次。
- **延迟仍然是约束**：成本不限，但模型单次调用仍要几秒。所以实时操作一律交给控制器，模型只做秒级以上的决策（见第 7 节）。
- **并发**：两个参谋可以并行调用；总指挥串行。方针更新后，两个参谋在下一轮读取新方针。
- **一致性风险**：参谋读到的方针可能晚一轮。由合成器在下发前用最新方针再校验一次来兜底。
- **能力虚设风险**：意图里有、执行层没有的字段，第 1 阶段只记录不执行，并在复盘页明确标“未执行”，避免看起来生效。
- **评估成本**：实机对局慢，是最大瓶颈。用 computer use 挂机连续开局来缓解（第 9 节）。
- **单位借用风险**：直接控制与原生 AI 抢单位，是直接控制能否成立的关键，放在第 3 阶段最先验证（P0）。

## 12. 指挥官性格：做一个难缠的对手

负责人的期望（2026-11-20）：前面几节只是一套打对局的思路；更重要的是，指挥官要有自己的性格，让对手觉得它难缠。三位指挥官（铁锤、堡垒、幽灵）的角色设定和战术设计见 [指挥官角色与战术设计](commander-characters-tactics-20261120.md)。

### 12.1 原则：性格必须改变决策，而不只是改变语气

现有的风格系统只是把一段说明塞进提示词：五个维度（进攻、冒险、经济、侦察、追击，每项 1–5 档）、三种打法（突击、防守、机动），再加至多 1200 字节的自由描述（`integration/host_runtime/profiles.py`）。这种写法对决策的影响不可控、也测不出来，所以改成：

- **性格是一组参数**，直接作用到每一层的选择和控制器参数上，同时保留一句话的自由描述，用来定性格的口吻。
- **同一性格前后一致**，但带有适度的随机性，不让对手一眼看穿。

| 性格参数 | 作用到哪里 | 例子 |
| --- | --- | --- |
| 进攻性 | 总指挥选路线；战术参谋选姿态 | 高：更早出手、更少龟缩 |
| 冒险 | 开局方案选择；All-in 的门槛 | 高：敢于贪经济或速攻 |
| 纠缠度 | 骚扰控制器的频率和持续时间 | 高：不停地摸你的矿车，让你没法安心发展 |
| 惩罚意识 | 事件触发规则 | 发现你扩张、科技或主力离家时，立刻打你的薄弱点 |
| 惜兵 | 控制器的撤退血量阈值 | 高：打不过就跑，保存单位反复骚扰；低：以命换命 |
| 诡诈 | 战术参谋的佯攻和多线进攻 | 高：一边佯攻正面，一边偷袭矿区 |
| 记仇 | 总指挥选主攻对象 | 高：盯住同一个对手或同一个弱点反复打 |
| 适应性 | 跨局记忆的使用强度（见 12.2） | 高：同一招不会让它吃两次亏 |

### 12.2 跨局记忆：让它“记得你”

难缠的关键是它会针对你。为每个人类玩家保存一份只来自己方合法观察的记忆，例如：
- 你通常什么时候扩张；
- 你的防空、反装甲是否薄弱；
- 你偏好的进攻路线；
- 上一局它是怎么输给你的。

开局前，总指挥读取这份记忆来选开局方案和主攻方向。性格里的“适应性”决定它多大程度上利用这份记忆。只记录合法观察到的事实，不读取对手的隐藏信息。

### 12.3 让玩家感受到性格

- **决策记录用性格口吻写理由**。复盘页能看到它当时怎么想，例如“你又在 4 分钟扩张了，这次我早有准备”。
- **局内表达**：先在客户端的实时决策流里显示；局内聊天或电台等可行性确认后再做。
- **赛后**，复盘页展示它针对你做了什么，以及它下次会怎么调整。

### 12.4 性格的评估

- **客观指标**：骚扰次数、敌方矿车损失、对手被压制的时长（基地受威胁的时间占比）、抓住弱点的次数、开局方案的多样性。
- **主观指标**：赛后让玩家用一键打分评价“难缠程度”和“像不像一个有性格的对手”，结果写入评估数据。
- **对照**：不同性格在同一条件下对比，确认性格参数确实带来可观测的行为差异，而不只是理由的措辞不同。

### 12.5 实施位置

- **阶段 1a**：性格参数进入合同，三层提示词和控制器参数都读取它。在 UI 的“AI 风格”页把旧的五维五档替换成新的性格参数，并提供几套预设性格。
- **阶段 3**：骚扰控制器上线后，纠缠度、惜兵、惩罚意识才会真正生效。
- **跨局记忆和主观评分**：放在阶段 2 实机对照之后实施。

## 13. 负责人决定（2026-11-20）

1. **执行边界**：允许直接控制单位。约束是模型不进实时循环，由控制器执行（第 7 节）。
2. **能力优先级**：认可开局决定胜负。链路为：侦察 → 低成本骚扰敌方矿车 → 迅速发展 → 快速攀 T3 → 中期动态作战；电力与矿车博弈最关键。优先级按此调整（第 6、8 节）。
3. **成本**：暂时不考虑。
4. **评估资源**：Windows 上用 computer use 开局，可以挂机连续开。
5. **指挥官性格**：打法思路只是基础，指挥官要有自己的性格，让对手觉得难缠（第 12 节）。
