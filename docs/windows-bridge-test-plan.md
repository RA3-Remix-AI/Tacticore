## 后续顺序与通过标准

1. **完成候选 V7 的离线验收链。** 补齐 `formation_mission_qualification.py`、独立 `retreat_departure.py`、配套用例与 Python 冻结清单；核对实际 DLL、host、源码、ABI 和全部依赖。98/99 必须绑定真实首路点、只允许一次启动窗口、30 模拟帧和 350 距离硬上限；保留离点 25、到家 15×3、双正常归还及固定任务期限。完成静态审查后才开放独立诊断入口，普通宿主仍需真实效果源。
2. **验证新默认模型后端。** 先检查指定库和凭据，再做无游戏执行的真实端点探针，核对取消、超时、本地接续、实际 wire 预算和已压缩任务记忆。历史 DeepSeek/legacy 请求不算 PydanticAI 供应商兼容性证明。正式整场启动器应提供明确的 `--library` 透传，避免误读空的新默认目录。
3. **实机复测协同与异常撤退。** 全新会话、真实原生电脑、公开 10000 资金，优先双方中等以避免对手过早结束。分别验证完整接近→交战→撤回，以及旧死锁间距约 246.4 的退程启动。核验真实移动轨迹、指定目标来源伤害和耗弹、防空兵队形、两个原始起点的物理到达、正常归还与 13 处真实入口恢复。96/97、失视野及重获分支未出现时明确记为未覆盖，不能算通过。
4. **重新打一整场模型对原生电脑。** 只有攻击、经济骚扰、协同三项都具备相应真实效果源后，才新开双方中等/10000、model enabled、无校准派单的正式场。记录生产入队、实际花费、出厂单位、无效命令率、策略变更频率及任务完成率；独立核对自然结算与控制释放。至少一条实际接受的压缩上下文须在战略 TTL 后仍保留进行中任务。胜利或派单成功均不能替代三项实际效果。
5. **新桌面端到端验收。** 先实现受控 Windows 适配器与原生凭据管理，再测试真实预检、短期就绪令牌、具名多指挥官与连接复用、重复请求去重、停止等待、断线和换局失效。沿用 `windows-handoff.md`，为真实能力摘要单独扩展证据范围，不能将 demo 标签整体替换成 verified。完成 CLI 正式场后，再从新 UI 的真实开始按钮跑到结算；前端构建、UI 演示与历史 CLI 对局各自记录。
