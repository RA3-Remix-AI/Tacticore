## 职责边界

| 事项 | 弈核/模型决定 | 原生 AI 负责 |
| --- | --- | --- |
| 建造、经济与科技 | 建什么、投入优先级、扩张方向、科技时机与预算 | 施工与队列执行、合法落点、采集等具体行为 |
| 侦察 | 侦察区域、优先级、时机、信息需求与可投入兵力 | 侦察单位具体移动、自卫和局部交战；回报合法可见信息 |
| 兵种生产 | 根据情报决定兵种构成、数量、比例、补充与克制关系 | 原生生产执行；单位出厂后继续进入原生 AI 的部队管理 |
| 部队调度 | 哪支部队承担哪个区域的集结、进攻、防守、增援或撤退任务 | 战术展开、寻路、阵型、局部目标选择、攻击、技能、让路等操作 |
| 战况调整 | 是否改变战略、调整投入、换目标区域、取消或替换高层任务 | 在被接受的战略约束内继续执行原有战术逻辑 |
| 停止指挥 | 停止模型请求和新增宏观意图，核对未决指令 | 继续原生游戏行为；不冻结单位或强制全军回家 |

“调度”不得在适配器内部退化为模型逐个接管演员、连续发送 Move/Stop/Attack 或指定弹药/开火次数。高层命令须由原生战略、建造、生产或部队任务机制消费；接口尚未验证时明确记为待实现，不用提示词或仅落日志代替执行。

## 架构

```text
客户端配置 → 整局宿主 → 己方可见战况与持续记忆 → 模型宏观计划
                  ↓                              ↓
             统一证据账本 ← 意图校验与预算 → 原生 AI 高层适配器
                  ↑                              ↓
             执行与战况反馈 ← 原生建造/生产/侦察/部队任务机制
```

计划表达目标、资源、优先级、条件和有效期。模型不接收内存地址或逐帧控制接口。适配器验证会话、指挥官、预算、科技前提、信息年龄与任务冲突，然后记录原生接受、拒绝或未知结果。原生接受不自动等于产生效果。

沿用现有客户端、身份映射、真实模型连接、配置修订、记忆、生产账本及可见信息采集等有效成果。微操控制器、近场攻击、shot/damage 探针和逐单位归还实验作为历史研发资料冻结，不接入新宏观模式，也不删除原始证据。
