# 近场原生工厂与独立v2通道

本阶段将原Owner、独立准入和原生观察器接成可构建的执行图，并定义独立通信ABI。尚未装入游戏或发布客户端能力；活动d168及其25份声明输入、3个制品保持不变。完整G0–G8继续active。

## 原生工厂

`near_native_factory.cpp`从固定SHA的原`native_factory.cpp`复用真实游戏内存读取及原生产器映射核验，原producer函数文本逐字保留。新构造器先检查绑定、schema2、禁止诊断故障位、固定构建/源策略及真实原生产付款回执，再对同一演员取得两份出生观察，进入原Incarnations。不会接受调用者提供的generation或born_frame。

工厂在安装钩子前创建全部依赖：目标注册表/读取器、武器读取器、默认拒绝的准入转接、观察器、原MemoryIO、组合Owner及NativeAdmission，最后一次性连接转接。动作只能经Observer正常facade执行，出生核验、私有home、借兵source2、Stop3、原租约900帧/120秒与物理归还逻辑继续由原实现承担。

查找目标只接受当前绑定下注册表产生的key。`resolve`对失效key、不同绑定或已退休记录返回空；丢失后重新可见仍需新配对和新key。公开ContactView只有key、类型、帧/时间、当前位置和生命，没有目标地址。视野检查使用电脑3自身完整footprint，读取预算50毫秒/次、目录最多64个，未观察到的记录不充作当前可见。

新工厂在90秒后拒绝新工作，工作到期时间不得超过工厂启动后120秒；150秒请求正常停止。独立helper保留180秒硬循环和10秒清理宽限，原租约预算不因通道启动重置。模块在激活前固定，部分安装无法安全恢复时保留完整对象图；隔离容器的容量在安装前分配，避免错误路径销毁仍被trampoline引用的对象。

目前没有真实射击/伤害生产器，Execution不会填造Damage，因而不能取得命中信用。原6/7恢复及故障注入不自动移植为组合恢复权限，新工厂明确拒绝这些尚未验证的操作。未知后需要单独的组合恢复建设和实机验证。

## 独立通信协议

新mapping为`Local\\TacticoreNear2_<pid>_<token>`，magic为`0x544e5232`，版本2；消息、DLL、helper和导出名均独立于活动v1。移动命令值继续复用原结构，外层仅接受v2绑定。攻击Intent及预先授权的原ReturnHome命令使用同一个发布世代一起提交，不能把两次计划的返回命令拼在一起。两路经过同一Owner的命令ID和全局序号检查。

新WireResult用固定96字节原因代替进程内字符串指针。移动、攻击、当前观察、可见key目录及近场事件分别有发布世代或ticket；512个近场事件保留溢出计数，不掩盖丢失。异常、绑定编辑或控制状态Uncertain会锁住旧对象图，后续回调不继续推进SDK动作，也不允许新bootstrap替代旧owner。停止请求不能被当作未知结果的自动恢复。

终态必须同时没有移动和近场持有、没有活动回调。实际装入后的Released必须具有15处完整恢复掩码32767，旧8191不通过；在安装前安全拒绝仅接受Refused及无钩子标志1。helper退出不会卸载目标中尚未清理的内层钩子。

## 资格采样入口

`near_factory_probe.py`复用原付费producer/绑定采集，在新mapping构造v2启动参数；只接受`near_factory_channel2_readonly`、模型禁用、真实大厅已核验的owned会话。它不能提交移动/攻击，也不能提升为普通能力。任一路命令世代意外变成非零即拒绝；退出同时检查两个held及新恢复掩码，再独立读取15处入口字节。

原始启动、出生、绑定、事件、钩子、双头与最终完整二进制分别保留。采样器、原transport、两份布局和producer源码SHA在构造时记录并在运行中复核，变化即拒绝。观察超时不能重新attach：保留原helper句柄及映射，核对同一实例的状态。入口现已完成下面限定范围的实机验证。
