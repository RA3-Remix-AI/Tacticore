# 开发中原生攻击归属与待发攻击取消

本记录晚于 `runtime-near-combat-owner-checkpoint-20261027.json`。新代码没有装入游戏，没有新 DLL、客户端发布或能力授权；活动 d168 及 candidate13 不变。完整 G0–G8 仍为 active。

## 实际代码

`near_attack_lineage.h` 记录一个已绑定演员、任务、租约、目标 key 与全局序号的 opcode11 请求。它分别核对 `0x572280` facade、`0x787500` dispatch、`0x830220` copy、`0x830320` unpack 和 `0x76e690` private 交付。来源必须为 1、请求次数必须为 1，正常 private 调用者为 `0x785dd0`；source0、无限次数、不同目标、不同存储/解包地址、失效时钟和重复交付不能成为自己的动作。

copy 中目标指针转换成 object ID，unpack 后必须重新成为相同的目标指针。先前保存的记录、一个 own_scope 标记或未匹配的解包输出均不能代替完整链路。该类只证明请求/交付；不生产射击或伤害事实。

`near_native_hooks.cpp` 是活动 `hooks.cpp` 的独立开发副本，原文件 SHA 为 `a4789567b350f6f779a5913b55c87f6df60706653b5198aa86d740fef74c0262`。它保留原移动、停止、姿态、转交和原生让路检查，添加攻击 facade 和武器 getter，总计 15 处钩子。新的正常攻击调用经过 `0x572280`，不直接调用 private 入口或 trampoline，不写状态、路径、目标或武器次数。

`NativeAttackAdmission` 在第一次 SDK 调用及延迟 private 交付前分别检查，默认拒绝。未来实现必须从原 Owner、原生目标注册表、己方视野和武器重新取得证据，不能由模型字典中的 bool 放行。当前还没有提供可在实际游戏中准入的实现，也没有发布 bootstrap/共享 ABI。

观察器目前每个实例只允许一次攻击 SDK 尝试。后续重复战术需要在新的完整租约和序号合同中处理，不能靠重置 used/attempted 标记绕过。现有 NativeHost 180 秒生命周期限制不会因该原生对象的编译自动得到继承；新运行时接入时仍须明确保留。

## 武器观察

新 getter 包装器在原调用返回后检查实际选择的 AK47 武器条目：容器/槽/条目归属、模板及 asset 头、弹药、状态机和反向指针都要读取完整。`WeaponReadyState` 对应状态 0、vtable `0xc1fd18`、状态机 `0xc1fc50`，且当前请求标志为零。该对应关系由固定 SHA 游戏的构造器、名字 getter 和原生状态读取函数共同核对，不能从“ammo > 0”推导 ready。

private 原调用结束后另读同一条目的请求次数是否为 1，并保存前后值。它仍不是实际发射数量或命中证明；选择改变、读失败或次数不符会撤销归属并保留未知。尚未建立真实射击与伤害的关联生产器。

## 待发攻击的正常 Stop 替换

移动 v1 的 copy 要求原存储槽为空。撤回还未解包的攻击时，真实槽为 opcode11；把它改报成空槽会伪造事实。

新 `AttackLineage::PendingReplacement` 只能由当前攻击实例产生，封装当帧、线程、演员 update、攻击 command ID 和完整 96 字节原记录。只有仍 pending、未解包、未开始解包、未交付、无嵌套 dispatch 的相同记录才可取得证明。工作 TTL 已过期不阻止原 Owner 发安全 Stop，也不会延长旧攻击许可。

`near_move_lineage.h` 是活动 `lineage.h` 的独立副本，原 SHA 为 `e99baa0880d82a0f8ac9cd88f9f0f9738d44b6a0a591699c1507da5ca0636e0d`。唯一行为扩展为：正常 Stop 的 copy 可接受匹配的封装替换证明；Move 和其他命令仍不可以覆盖该忙槽。原生 copy 返回后的真实新记录还必须符合完整 Stop 载荷，之后旧攻击才标记 cancelled，新的 Stop 沿原 unpack/private/Stop3 流程完成。

记录 13/14 保留真实替换前后字节，新增记录 45 关联被取消的原攻击身份。已经解包或交付的攻击不能被这个证明标记为取消。观察器不吞掉原生调用，每个被拦截的原函数仍只转发一次；检查失败保持 foreign/unknown，不能宣称旧命令已取消或绝不会发射。该取消分支目前仅通过显式模拟回放，仍需实机证据。

## 验证与接入门槛

- 近场回放共 47 个独立组：控制器 15、目标读取 11、组合 Owner 9、攻击归属及取消 12；x86/x64 分别执行，共 94 次组执行。
- 新原生观察器与真实 Win32/MinHook 依赖已完成 x86 编译和链接。另 3 个边界组只构造未安装的观察器，检查默认拒绝、无 SDK 调用和未安装对象的关闭；不读游戏进程，不证明安装或实机归还。
- 原 51 组 C++ 测试体另用新的 NearMoveLineage 执行，覆盖未携带替换证明时原有移动/停止行为；原测试和活动实现均不改写。这是独立的原内核回归，不计为 51 个新增近场组。
- 运行时 Python 99 项包含实际编译、PE 架构、源/产物 SHA、独立重放及活动 v1 输入/输出哈希核对。
- 原生静态审计扩为 24 个字节/相对调用点和 16 段反汇编。`0x79bde0` 参数为目标模式 0/1，而不是目标 object ID；它和对象射击函数仅是后续真实关联钩子的候选，未作为任务伤害证据。

首次冻结编译遗漏 MinHook 的 `pstdint.h`，失败目录/日志保留，补齐依赖后的冻结构建已通过。之前错误的 x64 标记及其独立纠正记录也继续保留。

实际接入前仍需：独立可见目标/武器读取和精确 build 策略、原 Owner 的新原生工厂与 ABI、射击/伤害关联，以及受控游戏中的正常交付、未交付取消、丢视野/停止/死亡和回家/归还验证。新观察器完整关闭应核对 15 处恢复掩码 `32767` 及新入口原字节；不能拿旧 d168 的 `8191` 或原 19 入口证明新观察器已关闭。生产及被动观察器仍需独立核对。
