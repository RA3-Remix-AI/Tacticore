## 源码边界已落地

`integration/host_runtime/macro_control.py`在Host读取会话/凭据之前拒绝旧tactical、runtime及恢复证据。`battle_host.py`不再实例化`ModelRuntimeTasks`，已构造的macro Host在单兵attach/reserve/commit和生命周期切换入口明确拒绝；现有停止/只读清理逻辑保留，避免用新模式阻碍旧状态核对。

桌面run.check、run.start、实际launch和NativeChecks都检查宏观边界；不能由已登记的历史微操证据生成新启动许可。旧登记仍可读取和校验SHA，供历史状态/记录核对。实际启动参数显式包含`--control-mode macro_native`，不再转发旧微操证据。

当前Host的模型上下文明确单位操作属于原生AI，缺少消费者的宏观领域保持unsupported。日志状态标出control_mode和unit_operation_policy。这些标签表达产品执行边界，不冒充新建造/侦察能力已经实机通过。

新增6项真实Host/桌面入口测试通过；包括实际构造Host且没有单兵调度器、真实状态导出、在凭据/游戏访问前拒绝旧证据、单位入口零attach、桌面许可和派发拒绝。相关56项检查通过，随后完整`test_host_runtime_*.py`共442项通过。全部是明确假游戏/假provider检查；没有游戏/模型调用，也没有发布新客户端。

最初回归中旧测试仍期待微操证据进入Host参数，按用户要求更新为“可读历史登记，但不能生成宏观启动许可”，同时保留SHA篡改和未决启动不自动重发检查。两次完整回归的失败日志保留，最终v3通过，不改写旧实机结果。

## 固定游戏与SDK审计

`native-ai/audit_macro_interfaces.py`只读精确SHA的游戏PE和6份本地SDK schema，核对14处固定字节/相对调用，保存5段反汇编；不打开进程、不注入、不调用游戏API。输出为`reports/native-macro-interface-static-20261027-v1/audit.json`。

- 战略setter `0x8a0940`写directive并处理原生事件、旧信标和期限，wrapper `0x8a0a90`还有反馈；直接改enum字段不能替代正常调用。schema还包含强制值为-1的Invalid哨兵，不能将它计入Normal=0开始的五个有效值。本次审计初版因没有列入该哨兵而拒绝，按实际schema补全并检查forceValue后才通过。
- `SKIRMISH_AI_MAKE_BASE` case `0x5ac025`调用`0x584250`，经Player+0x90解析AI，解析命名waypoint，最后对AI+0x458调用`0x8b5770`。该链是基地管理操作候选，不能当作任意建筑生产或精确放置接口。
- co-op信标接收有关系限制。玩家参数存在不等于能控制独立电脑，也不允许错发给人类。后续须验证完整目标上下文或选择适用于独立电脑的高层消费者。
- SDK的AIBuildState、AIBudgetState、AIStrategicState、TeamTemplate提供优先调查方向；schema存在与静态ABI候选不证明实时切换、模型采纳或实战效果。
