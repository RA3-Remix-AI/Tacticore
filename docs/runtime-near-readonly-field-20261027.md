## 读取及隔离边界

新组件为 `near_readonly_probe.h`、`near_readonly_probe_dll.cpp`、`near_readonly_probe_host.cpp` 和独立 Python loader。x86 构建位于 `reports/near-native-readonly-probe-20261027-v2`，DLL SHA 为 `0e0ea518d87d5dc6c079924f9d0e5882170d2ceac42623d6cf31748b549342ec`。首个Host警告构建失败目录保留。

采样器只通过独立 WH_GETMESSAGE 外层消息在真实游戏线程读取，未安装游戏入口detour。每次绑定固定进程创建时间、线程、会话、指挥官UUID、原生owner及exact-build game/mod/视野能力和模板审查hash。武器读取检查容器/槽/条目/asset/状态机及反向关系；就绪还要求原生 WeaponReadyState0、AK47、弹药、请求标志和状态机标志匹配。

目标沿 `near_target.h` 的原生列表、敌我关系、保守模板源审查、完整当前footprint和电脑3视野配对检查进入注册表。观察者画面不授权目标；未导出不可见敌人的当前位置。源审查与固定构建绑定不等于完整反编译隐形逻辑，仍只接受保守征召兵范围。

独立审查器 `reports/review_near_readonly_field_20261027.py` 直接按固定x86布局解码原始共享内存，重核bootstrap/会话/进程/线程、发布ticket、全部导出记录、武器反向关系及就绪条件、目标key身份/己方视野字段和不可用记录清零；不打开游戏。30份构建、读取器及依赖来源另行冻结，原始数据与当前/冻结审查结果分别保存。

三段全部结束后，另起只读进程再次确认三个helper均已退出、终态无活动回调，并从仍活的同一游戏读取15处入口原字节，与磁盘及各段preflight一致。之后仅结束本轮owned fixture；这是有界诊断结束，未自然结算。原session保持不变，活动索引单独标记fixture_ended。
