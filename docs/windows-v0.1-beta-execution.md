# Windows v0.1-beta 发布执行清单

本轮从 `5238c9cb` 的独立分支 `release/windows-v0.1-beta` 开始。目标是普通 Windows 用户在没有源码、Python、Node、Rust、编译器及历史验收目录的电脑上安装、配置并完成受支持的自然对战。本文的待办不是已验收能力。

## 产品及验收边界

- 指挥官只负责高层战略意图、跨轮记忆及公开理由。原生 AI 负责建筑、选址、生产数量、兵种与微操。
- 首版仅开放已证明的游戏/Mod 版本、地图、P3 苏联及出生区域组合；通过哈希和实际局内身份检查限制范围，不能只看文件名或 UI 选择。
- 保留合法视野、PID/创建时间/会话/租约绑定、过期响应隔离、未知不重发、容量限制、停止后无新增指挥及独立归还。
- v9 的 F01–F07 和三局自然结算保留原结论。它们不构成新 Native 二进制、安装器或本次发布候选的验收。
- 唯一实机控制者仍是会话 `01a1856c-3b1e-7413-a45c-f2aa2db875c9`。本分支先做离线工程，不启动第二个游戏、调用真实模型或认领旧局。

## 已确认的发布阻塞

1. Native5 `host.cpp` 固定 `E:\RedRar3\Data\RA3_1.12.game`。
2. Native5 `profile.h` 生成器嵌入开发源码、工具链、日志及 Mod 根目录的绝对路径；DLL 实际锁定这些文件。重新签发一张 JSON 证书不能使旧 DLL 可移植，不能删掉校验来凑安装包。
3. Native5 SDK 输出及归还日志固定在仓库 `reports`；要与新 Native 候选及只读孤儿归还读取器一起迁移，不能只改 Python 写入点。
4. schema13 资格加载器依赖原始研究包、旧局原件、开发机 EXE 和绝对源码清单。需要新的发布资格合同，保存证据溯源，并重新验证新候选；不能修改历史报告或把研究通过当作新产品通过。
5. 旧 companion 打包器仅包含早期 Native1/生产制品，不包含完整 Native5 运行闭包，且曾复制整个 site-packages。禁止沿用其成功退出作为本次发布成功。
6. 安装器目前禁用。游戏/Mod/美术及第三方组件的实际再分发范围需要逐项核对；不把本机游戏、Mod、工具链或 SDK 整包带给用户。

## 当前交付与后续门槛

第一批只产出独立 Python 阶段包及机器可读预检。阶段包不具备游戏控制资格，也不是可对外发布的 beta。预检发现上述 Native5 旧合同会返回非零，保留明确原因。

第一批实现及实际验证已完成，见[2026-10-31 基础设施结果](windows-v0.1-beta-foundation-20261031.md)：发布回归 14/14、Rust 回归 13/13，仓库外独立包首用/查询/重开通过。阶段 A 的完整发布闭包、含 wheel 摘要的构建输入锁及再分发审查仍须随之后的候选补齐。

阶段 B 必须以新 Native 候选实现；阶段 D 的安装器只有在 B/C 可运行后才开启。自动更新、多地图/阵营、更多提供方、实机重大损失/基地遇袭事件源及额外演出暂列 P1。

最终公开上传、代码签名证书和项目许可选择在真实安装候选可审阅后处理。本轮启动开发不等于已经授权公开发布或购买证书。
