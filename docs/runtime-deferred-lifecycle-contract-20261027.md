# 有界准备与延后原生通道接续

当前代码与组合测试通过，candidate12已构建；尚无本次延后接续的实机结果，不能替代180秒或模型移动验收。

关闭和授权拆成两个阶段。`retire_for_later`沿用完整原生关闭/控制归还审查，记录不可变report/capture及其SHA，并创建只表示已关闭的`RuntimeRetirement`；没有next binding、next run或actor授权。只有新的付费单位完成且只读可用性预筛满足时，可信Host才调用`authorize_deferred_successor`，重算关闭来源、核对账本无未决，并以当时的全局高水位生成一次性的固定actor选择和新绑定。后续attach仍独立证明原始付款、出生、世代及真实原生准入。

普通移动及可选首次回家恢复pin在关闭前、延后授权前和新绑定attach前分别重核。缺pin不能静默降级。授权或attach不确定后不自动重试；旧失败、旧通道和旧控制记录不改写。已关闭且等待后继期间，Host不再poll旧native transport，也不把关闭凭据当作新权限。

准备分两层：未装通道前，从当前己方存活清单和只读可移动/地面状态过滤已付款候选；装通道后仍等待独立三帧home静止/空位和原生端点。候选或通道连续30秒未就绪就结束本次准备，已安装通道先独立关闭。模型收到typed准备状态，知道普通己方单位总数不能替代付费预留；只有真实`runtime_opportunity`中的地点可被提交。不会从准备状态制造任务成功或原生权限。

本机单个Native Host的180秒硬边界不更改。90秒后不接新租约并开始空闲通道退役；已有活动任务在120秒发一次停止，保留清理余量。暂停时不发新动作，未知命令仍要求独立恢复。退役遇到已派发生产的账本屏障时暂停新的生产，等待现有回执结束后再关闭，不能忽略未决命令。正常生产另外遵守150帧最小间隔。

新任务派Reserve前、Ready后都读取最新原生时钟和暂停标记；Host战略快照未刷新也不能延长模型计划TTL。已提交任务继续使用固定目标及原生租约，不能由新计划暗中改写。

Host状态保留最近任务历史与局部任务的实际home/归还事实；客户端分开显示准备、执行和事实核验，不把“就绪”显示成“已完成”。局部动作不增加主攻、骚扰或协同的效果计数。跨180秒等待、全局序号连续和新付费演员切换已用真实Host/SQLite及显式模拟native IO验证，仍需实机。多epoch宿主的最终独立释放审查及完整G4/G6–G8目标继续保留。
