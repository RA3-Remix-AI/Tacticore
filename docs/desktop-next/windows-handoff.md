# 弈核桌面与 Windows 执行端交接协议 v1

状态：唯一桌面工程为 `desktop-ui/` React + Tauri，工程契约与离线演示已定义，Windows 原生适配器待实现。原 Windows GUI 已移除；当前实机开发使用宿主 CLI。此文档不授予新游戏能力，也不替代既有实机验收。

## 分工与边界

`desktop-ui/` 负责界面、可理解的状态、玩家操作和离线演练。Windows 侧继续维护策略、模型、会话绑定、生产和战术执行。原生适配层应读取既有宿主协议，不改变策略算法、指挥权限、证据阈值或既有日志。下述检查、启动和状态验证是未来适配器的实现要求，尚不是当前 Tauri 的能力；不保留或复制旧 C# 桌面实现，也不建立历史兼容层。不能直接把路径、进程命令或凭据暴露给 WebView。

真实接入采用最小的命名操作，不允许“任意命令执行”“读取任意路径”类通道。前端只提交稳定档案 ID、配置修订、会话 ID 和请求 ID。原生端自行定位已注册配置与当前会话，重新核验游戏、适配包、执行器、凭据引用和能力证据；UI 显示“可用”不是授权依据。

## 公开契约

TypeScript 类型以 [`desktop-ui/src/runtime/types.ts`](../../desktop-ui/src/runtime/types.ts) 为准。

| 字段 / 操作 | 语义 |
| --- | --- |
| `schemaVersion: 1` | 消费者不识别的主版本必须拒绝，不能猜测兼容 |
| `mode`, `adapterConnected` | `demo` 永远是模拟；原生连接必须独立握手，不能从运行平台推断 |
| `revision` | 同一观察流的单调递增状态版本；相同或倒退版本不得覆盖新状态 |
| `profile.id/revision` | 档案稳定身份与配置版本；改名不等于改身份，任何执行相关配置变化应递增修订 |
| `session.id` | 当前对局身份，不能跨场复用；无有效会话时为 `null` |
| `readiness.token/expiresAt` | 短期检查凭据，当前演示有效期 20 秒；开始必须由原生端再次校验 |
| `capabilities` | **只读显示摘要**；demo / unavailable / planned 均不是实时执行权限 |
| `tasks`, `metrics`, `logs` | 给用户理解的脱敏摘要，不含 Key、认证头、精确私有内存地址或任意可执行文本 |
| `check` | 可取消的只读预检；允许本地采样但不能因检查而发起付费模型请求或派单 |
| `start` | 带 request/session/profile/revision/readiness；完整重验后才允许调用既有宿主 |
| `stop` | 写匹配会话的有界停止请求；等待终态，不 kill 游戏或不相关进程 |
| `detach` / `attach` | 只停止/恢复观察，绝不能隐式停止/重启宿主 |

当前 `capabilities.status` 特意不定义“已获得真实执行授权”的值。真实接口接入时应单独扩展有证据来源与范围的摘要结构，经协议审阅后才允许显示“实机可用”；不得把所有 demo 值整体替换成 verified。

## 原生检查、启动与指纹合同（待实现）

1. **固定操作入口**：原生端定位受支持的 Python 解释器、宿主脚本、当前会话与注册档案。前端不得传入任意可执行文件、命令行或文件路径。检查与启动使用同一解释器、同一完整参数绑定。
2. **检查不执行**：调用宿主只读预检，验证游戏身份、进程创建时间、当前对局、玩家、指挥官、连接、适配包、能力证据与执行器状态。预检不得发起模型请求、注入桥接或派单；允许产生标明来源的本地采样记录。
3. **冻结检查依据**：生成短期 readiness token，绑定 session/player/profile revision 与检查输入的字节指纹。至少包含宿主及其策略、模型运行层、视野、战术执行依赖的源码或发布清单，Python/依赖版本清单，模型配置引用与修订、适配包，以及所依赖的证据清单和原始证据文件；不能只哈希顶层脚本。凭据只绑定安全存储引用与版本，不向前端泄露内容。
4. **启动再次核验**：启动前重算全部输入指纹、当前游戏/会话身份与 token 期限。任何差异都清除就绪状态并要求重查。取得 session/player 互斥租约后只启动一个受控宿主；记录宿主 PID、创建时间、固定脚本与会话参数，启动回执丢失时查询该身份，不盲目重试。
5. **独立核验观察与停止**：读取状态前确认 schema、来源、session、玩家、指挥官、连接、宿主进程身份、适配包与记录新鲜度。需要停止时再次核验这些绑定，仅向该宿主的固定停止通道发请求，等待明确收尾回执；错误或失联状态不能显示为已停止。

真实原生适配器还必须自行定义允许的输入清单与发布完整性规则。当前演示 token 和计时器不能替代上述核验。验收须覆盖“预检后更换模型运行层源码/依赖或证据，再点击开始”的拒绝路径。

## 状态机与请求一致性

正常路径：`idle → checking → ready → running → stopping → stopped`。预检失败进入 `fault`，重试重新进入 `checking`；检查取消回到 `idle`。配置修改清除会话检查结果。运行/停止中拒绝修改运行档案。正在检查时修改配置会使旧异步结果失效，不能重新点亮开始按钮。

- 每次操作有唯一 `requestId`。同一请求 ID 和内容重发应返回原结果，不二次派单；相同 ID 携带不同操作或数据必须拒绝。
- 演示提供内存中的有界幂等缓存。真实适配器必须将启动/派单回执持久化，跨进程重启不能因为缓存消失重发未知结果操作。
- 两个不同 ID 的重复开始同样不得创建两个宿主；执行端须持有 session/player 互斥租约。
- 检查取消只取消检查；不得把取消开始请求当成宿主已停止。如果启动响应丢失，应先查权威宿主身份，再决定 UI 状态，不能自动重试启动。
- `stopping` 表示请求已发出而未确认；只有匹配 session、宿主身份与可信终态才进入 `stopped`。超时显示“结果未知 / 待重新观察”，不能假报成功。
- 迟到响应须匹配 operation、profile revision、session 与观察序列。新会话开始后，旧会话终态不可覆盖新会话。
- 关闭窗口 / 取消订阅不代表停止真实宿主。断连后 UI 显示连接未知并禁用新执行；恢复后先读取权威状态。

## 凭据与数据

本预览没有真实 API 测试，不持久化密钥。后续真实密钥应由 Windows 原生端通过明确凭据 ID 管理，使用 DPAPI 或经审阅的本机安全存储；不要传命令行参数、写 localStorage、放状态 JSON 或诊断导出。前端连接信息只用于编辑非敏感字段。宿主默认配置目录为 `%LOCALAPPDATA%/Tacticore`，也可通过 CLI 的 `--library` 显式指定；当前 UI 没有真实配置写入或凭据保存器，不提供旧配置目录回退或历史迁移。

## Windows 交付前验收

1. 在当前受支持游戏/适配包下，校验没有游戏、多游戏、错误包、旧状态、错玩家、缺证据、缺凭据时均拒绝开始。
2. 修改连接或档案后旧检查失效；检查期间切页/取消不出现迟到授权；断线、宿主崩溃、换局后旧状态不能复活。
3. 连点、两窗口、重发同 requestId、请求超时再查状态，都不能产生重复宿主或重复派单。
4. 启动按钮完整经过真实验证并跑到结算；记录版本、场景、结果和失败任务。历史 CLI 整场记录不能当作当前 UI 端到端验收。
5. 停止请求在真实任务中进入等待，宿主明确收尾后停止；停止观察、关窗口、结束模型调用与结束游戏分别验证。
6. 演示与真实模式视觉标签、日志来源、能力范围保持区分；任何模拟样例不能解锁真实权限。
7. UI 与 Windows 两侧一起冻结协议版本和打包清单，再测试安装、路径空格/中文、更新、配置创建与修订、DPI 和窗口缩放。

当前源码与历史证据的 SHA 按字节绑定，Windows CRLF 与 Git LF 会改变哈希。接入前应先明确原始证据和冻结源码的行尾保存策略，不要为使检查通过而跳过哈希校验或改写历史证据结论。
