# 弈核 Tacticore 桌面体验扩展路线图

状态：备战室、指挥官工坊与战场电台的桌面本机交互已实现；真实游戏与宿主接线尚未完成。更新：2026-10-25。

本方案的体验主线为：**战前备战室 → 指挥官工坊 → 局内电台陪伴 → 战中态势与执行回执 → 战后复盘**。

弈核的价值应当在这些环节中被感知：玩家能准备一位有明确风格的指挥官，知道它正在关注什么，与它交流配合，并在战后看懂这场合作发生了什么。桌面继续采用深色、清晰、克制动效的独立战术科技风格；RA3 与 Remix 作为游戏适配主题，不限制弈核本身的产品身份。

## 已知现状与方案边界

本轮交付包括可持久保存 / 导出的本机备战计划、四类打法预设与五维五档偏好、行为说明与人格映射草案，以及基于 IndexedDB 的本地媒体 / 字幕素材、电台试听和事件演练。以下仍作为产品与接线合同使用；每项分别标明本机可用范围和真实游戏待接部分，不把离线交互当作局内功能验收。

| 项目 | 当前事实 | 本方案如何使用 |
| --- | --- | --- |
| 局内身份 | 用户已确认 Agent 以独立指挥官身份接入游戏 | 以“可交流的战场指挥官”设计体验，不重新虚构身份接入能力 |
| 局内电台 | 用户已确认右上角电台身份与通讯入口已经存在 | 作为局内陪伴的主要触点；与新桌面的通讯同步、媒体触发和调度仍待接线与验收 |
| 新桌面 | React + Tauri 六个工作区已实现本机配置、媒体管理和离线演练 | 本机交互与真实会话继续区分；尚未完成 GUI 实机接线 |
| 决策模型层 | 宿主 CLI 默认接入 PydanticAI，持续记忆、任务与执行校验仍由现有宿主管理 | 界面围绕真实状态和事件组织，不从动画进度猜测模型状态 |
| 当前倾向配置 | 旧百分比演示权重已移除，现为四类产品预设与五维五档偏好 | 保存与摘要映射已实现；尚未消费到真实宿主，不代表实力或胜率 |

| 视频关怀 | 桌面已支持本地视频 / 音频 / 字幕导入、保存、试听和六类事件演练 | 用户后续素材可直接导入；局内真实事件与游戏电台播放仍待接 |

## P0：桌面本机已交付，继续接通真实数据

本轮状态：

- **战前备战室**：地图、阵营、队友 / 对手关系、玩家索引、资金草案与独立执行限制可编辑、保存、恢复和导出；页面始终标记游戏未核验。
- **指挥官工坊**：四产品预设、五维五档调节、三类情景行为说明与自定义偏好已实现，可查看 / 复制现有三类人格对应的适配草案；没有下发真实模型。
- **战场电台**：本地视频、音频、字幕按指挥官存入 IndexedDB，提供试听、六类战况演练、频率 / 音量 / 静音 / 仅字幕、队列与冷却中断；每条 32 MiB / 90 秒，每位指挥官最多 24 条自定义素材 / 128 MiB，内置示例字幕不计入条数。实际解码取决于浏览器或系统 WebView。素材属于当前 origin；不同地址 / 端口与 Tauri 原生窗口不自动共享。
- **仍待接线**：游戏资金写入和读回、宿主消费偏好、真实局内事件触发电台、GUI 完整游戏控制与真实意图回执。

以下章节保留真实产品与验收要求；本机已实现部分不能替代对应真实数据的验收。

### 一、可视化备战与指挥倾向

备战室首先回答三个问题：**这场怎么玩、谁来指挥、现在能不能进入**。默认展示当前所选游戏与适配版本、地图、阵营、模型连接和指挥官；高级调试参数收起。检查结果按缺项给操作入口，例如“请先在游戏大厅设置初始资金”，避免只显示内部错误码。

配置分为四组：`MatchRules` 管地图、阵营、槽位与初始资金；`CommanderPreferences` 管软行为偏好；`ExecutionLimits` 管硬资源约束；`CommunicationPreferences` 管媒体和语气。指挥官角色形象与模型连接分开：同一角色换模型后保留形象、媒体与通讯风格。草稿修订与宿主已接受修订也分开记录，避免把本机保存当成宿主应用成功。

配置的保存与实际生效必须分开。建议状态如下：

1. **待保存**：仅为本窗口编辑内容。
2. **已保存**：本机配置持久化成功，尚未证明游戏已采用。
3. **等待大厅设置 / 等待适配器应用**：按该游戏支持方式给出下一步。
4. **已读回生效**：从当前大厅或会话读取到相符值，并展示来源与检查时间。
5. **战局进行中**：锁定只能开局决定的字段，显示本局实际值；编辑下一局配置须明确属于下一局。

**初始资金**由适配器报告可选档位、自定义范围或不支持，不在界面预设一个跨游戏通用金额。支持写入时，请求应用后仍须读回确认；不支持写入时，展示游戏内设置指引并核验读取值。若连读取也不支持，标记“无法核验，请在大厅确认”，不生成绿色生效状态。开局后禁止把 UI 修改显示成本局已生效。

**指挥倾向**已提供稳健经营、均衡应变、主动施压和侧翼游击四个产品预设，以及进攻时机、风险承受、经济投入、侦察积极和追击尺度的五档相对选择。预设对应现有三类人格与偏好摘要，不新增第四个后端 personality；均衡采用防守基底和中性偏好。阶段打法与局内重点仍待后续实现。每档描述预期行为，不表示胜率，也不保证 Agent 每次按该倾向行动。

当前引擎只有三类 personality 与 traits 文本可承接这些偏好。页面已能查看人格、生成摘要与独立补充偏好的适配草案，并校验命名预设与基底人格一致；该草案没有传入真实提示词。Windows 接线仍需处理配置版本、提示词预算与宿主接受回执，不能把本机五档值标成已生效的引擎参数。

**硬花费限制**放在独立的“资源约束”区，用数字和单位表达：生产总支出上限、资源保留底线。清楚标注它们限制宿主行为，不会修改开局资金。表单校验与宿主拒绝结果必须一致，不能把“软倾向”当作绕过硬约束的理由。

验收重点：保存后重开可恢复；当前值与下一局草案可区分；不支持的游戏字段不会假成功；实际读回值不一致时给出差异；现有演示权重不进入真实策略接口。

### 二、局内电台与关怀素材编排

电台承担指挥官的存在感，桌面负责准备素材、偏好设置与通讯回看。先复用已存在的局内指挥官与右上角电台入口，再验证新媒体与事件如何接入。

素材库每个条目展示：标题、对应指挥官、视频 / 语音 / 字幕、时长、语言、适合事件与试听按钮。用户提供的片段可按开场、局势紧张、重大损失、成功解围、完成目标和战局结束分类。试听是本地预览，应显式区别于向游戏发送通讯。

每条编排规则至少需要：触发事件、目标会话、优先级、冷却时间、同局次数、是否可被打断、是否允许视频和字幕替代。不要只用“当前资金低于某值”就频繁播报；可结合持续时间、事件合并和局势变化幅度减少噪声。事件条件必须来自适配器确实提供的事实，无法可靠观测时不启用对应规则。

建议设置三档关怀频率：

- **安静作战**：保留必要警报与关键回应，减少氛围片段。
- **标准陪伴**：关键战况和阶段性关怀，默认选择。
- **活跃电台**：增加情境通讯，仍遵守冷却与合并规则。

同时提供总静音、仅字幕、关闭氛围关怀和单条跳过。紧急警报可以打断开场或闲聊；短时间内相似损失合成一条。战况反转时立即丢弃过期闲聊和庆祝，不能刚失去基地还播放“稳了”。任务情报、战术回应与氛围关怀独立分类，玩家关闭关怀后仍可保留必要信息。

局内建议使用短促展开、自动收回的小型通讯窗。播放时才显示音频波形；字幕有足够阅读时间；视频默认不遮住操作核心区域。桌面回看可显示“这条通讯因何触发”，并联到当时的可见事实。首批按标签播放用户提供的预录素材，不依赖每条实时生成，也不描述成实时视频推理。

关怀语气贴近战场：承认压力、简短鼓励、给明确下一步。避免每次损失都夸奖、责备玩家或强行煽情；不能说出本方视野外的敌方位置、私有计划或资源。对手角色的通讯同样只能使用允许公开的信息。

验收重点：同一事件不重复播放；高优先级中断可恢复一致状态；过期消息不补播；静音和字幕立即生效；停止或切换会话后清理旧队列；素材缺失时可降为字幕且不阻塞决策；窗口隐藏后不继续全速解码；有真实事件来源前不把脚本播放标成实战触发。

### 三、当前意图、事实与执行结果

作战中心的主内容按三层组织，而不是持续滚动内部日志：

- **我看到了什么**：例如已观察到的装甲、资源压力和任务反馈，带游戏时间与信息来源；最后目击信息标明已过时。
- **我准备怎样做**：一句主要意图，说明优先目标以及什么条件变化会使它调整。
- **实际发生了什么**：宿主是否接受、任务是否派发、当前阶段与最终回执。

推荐卡片摘要为“观察 → 意图 → 改变条件”，点击展开事实、模型提案、宿主判断和任务关联。不要暴露内部思维链，也不要编造百分比置信度。关键状态须明确区分：提出、被接受、被拦截、等待资源、执行中、完成、失败、取消和被新计划取代。

持续任务可以显示“保持当前行动”，不必每次推理都播放一次进攻动画。失败卡片要能回答“为什么没执行、现在能做什么”，例如等待侦察、资源不足、会话已变更或当前适配器不支持。技术错误码和诊断字段放在可展开详情中。

验收重点：通过同一意图 / 任务关联标识还原提案与回执；不会把模型成功返回显示为执行成功；过期事实有时间提示；重新规划不抹掉仍在执行的任务；视图断连时显示最后更新时间并禁止继续伪装实时刷新。

## P1：从看懂到配合、再到复盘

### 战中伴随小窗

提供紧凑模式，只包含指挥官、当前意图、电台字幕、关键异常与控制入口。默认不抢焦点，可调整位置和透明度；普通桌面置顶窗与游戏内叠层是不同能力，前者可先验证，不能未经测试承诺支持独占全屏。

“暂停观察”“停止指挥”“关闭小窗”分别表达行为。关闭小窗只销毁观察界面；停止指挥要求宿主回执。可选通知只针对需要玩家处理的状态，不让每条决策弹出系统提示。

### 快速配合意图

围绕当前支持能力给“等我集合”“优先侦察”“守住这里”等操作；目标区域通过适配器认可的选择方式确定。Agent 可接受、提出条件或拒绝，并解释原因。玩家看见明确回应后，仍能跟踪等待、执行和完成，不以一条“收到”结束流程。

自由文本可先生成待确认的目标摘要，再交给受支持协议；不直接成为任意游戏命令。不支持的意图不出现在正常可执行列表中；对抗模式与搭档模式使用不同权限，不能让玩家直接控制敌方 Agent。

### 战后关键时刻与反馈

优先生成三到五张关键时刻卡：当时情报、主要意图、真正执行、结果和对应电台。玩家可按游戏时间展开完整时间线，筛选关键决策、受阻任务和通讯事件，并标记“这里帮到我”“这里配合不好”。

先做事件与快照复盘；录像同步作为后续增强。没有录像时不伪造战斗回放，没有可信效果归因时不标“这个决策赢下战局”。玩家反馈先作为复核材料，不直接改变下一局算法或自动训练。

### 模型延迟、用量与故障解释

默认只展示正在读取战况、等待模型、校验结果和等待执行等少量状态；技术面板提供请求耗时、超时、取消、拒绝原因和供应商返回的用量。区分网络请求耗时、排队与本地执行耗时，避免把所有等待都解释为“模型思考”。

供应商未返回 token 用量时显示未提供；费用只有配置了可追溯计价规则才估算，并标明估算范围。断线恢复和重试应由既有宿主策略决定，界面不自行连续重试。导出诊断保持脱敏，不能包含模型凭据或完整私密请求。

## P2：多 Agent 与长期玩法

在会话隔离、各方视野、资源竞争与执行权均验证后，再引入“选择搭档 / 选择对手”、多指挥官分工、不同模型同条件对照和观战席。多个档案不等于多 Agent 已可同时执行。

大厅可呈现各指挥官的偏好、通讯特点、当前适配能力和模型连接；不使用未经测量的综合战力评分。战中切换观察席必须遵守本局权限，不能通过查看对手 Agent 面板获取其私有情报。赛后对比需要相同场景与可解释指标，不能仅凭一场输赢给模型排名。

## 依赖与分期交付

### 用户指定的接续目标（2026-10-26）

状态：2026-10-26 用户已要求停止旧实机试错线，先完成 [架构建设与迭代计划](../architecture-iteration-plan-20261026.md)。本会话原接续目标已暂停，原主目标未完成；下面保留原交付范围，不再自动按旧串行顺序恢复。后续按新计划阶段门和用户实施指令推进。

前置完成后，接续目标为：对齐当前 `desktop-ui/` 客户端与真实宿主功能，让客户端配置（重点为指挥风格）实际被宿主和模型消费；以用户从客户端配置一名 AI、对战一名原生电脑并跑完整局为端到端样例，交付日志和过程记录。

验收要求：

1. 梳理客户端现有配置项，列明真实支持、待接线与不支持项；优先完成风格预设、五维五档、人格和补充偏好的真实映射。不支持的字段须明确提示，不能显示已生效。
2. 关联客户端配置修订、宿主接受回执、本局实际配置和模型可消费的偏好。展示已保存与已应用的区别；用脱敏记录证明风格到达真实决策请求，不以仅写入本机存储或导出文件验收。
3. 从当前客户端完成配置、预检、启动、观察和停止确认；以一名模型 AI 对一名原生电脑运行至自然结算。默认沿用前置已验收的场景，优先双方中等、10000 初始资金；资金不支持写入时在大厅设置并核验。胜负如实记录，不要求 AI 必须获胜。
4. 保存场景与版本、会话和双方身份、脱敏配置快照及应用回执、模型请求/响应的可审阅摘要、任务与执行回执、实际战术效果、失败与拒绝、生产支出、停止和控制归还、原生结算结果。按时间关联记录；不记录密钥或模型隐藏思维链。
5. 保存真实开始、关键交战和结算截图；条件允许时保存游戏回放或录屏，不具备记录条件时说明缺口。交付带时间线的过程报告、结果和日志索引，能从报告追到原始证据。
6. 风格应用与实战效果分别验收：配置到达模型且宿主确认，不代表模型每次行为符合偏好；用本局观察说明符合、偏离或不可判断。完整局必须绑定本次客户端和实际配置，历史 CLI 对局不能替代。

后续执行者应先读本节及 `windows-handoff.md`，再沿 P0-A 的真实接线推进。此接续安排不改变前置目标状态，也不将其未通过项目标记成功。

## 视觉与交互约束

- 维持深色独立科技风格，金色用于选择与强调，红色用于危险或需要处理的情况；不要让所有内容都像警报。
- 动效服务于真实状态变化：通讯接入、任务被接受、计划调整、回执完成。避免持续闪烁、虚构加载进度和遮挡操作的大型过场。
- 战中精简，战前和战后可展开信息。不要把完整配置表、角色介绍和长日志全部塞进作战中心。
- 支持减少动态效果、字幕、可辨识焦点与足够的文字对比；颜色不是唯一状态信号。
- 游戏主题可换肤，指挥官、模型、适配器、媒体和战局仍保持独立的数据身份。

现有使用流程见 [玩家指南](player-guide.md)，新桌面真实接线要求见 [Windows 接入合同](windows-handoff.md)，能力表述边界见 [品牌与宣传说明](claims.md)。
