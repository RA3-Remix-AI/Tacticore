# 弈核玩家体验与使用说明

本文先说明当前 Windows 原生客户端，再保留浏览器六工作区的离线演示说明。两者使用不同入口与数据，不会自动迁移。

## Windows 原生客户端 · 2026-10-30

当前本机开发预览可运行 `desktop-ui/src-tauri/target/debug/tacticore-desktop.exe`。它依赖已经准备好的仓库 Python 环境与本机运行组件，不是安装包；从仓库根目录启动：

```powershell
& '.\desktop-ui\src-tauri\target\debug\tacticore-desktop.exe'
```

窗口应显示“本机客户端 / 原生连接”。实际使用的可执行文件、软件与游戏包必须对应同一次冻结候选及版本清单。此前记录的 SHA-256 `168ebbad430c76cdd60c2b66bf3312737abd4e24bbceb0cc9657c6bf13cc57aa` 属于旧隔离预览构建，不能用于确认后来重建的客户端。浏览器里的“离线演示”不能启动真实指挥。

### 首次配置与连接修改

1. 若没有已有来源，在“本机连接配置”点“初始化本机配置”。它创建本机默认配置；遇到已有无关来源会拒绝覆盖。已有库直接点“重新查询连接”。普通使用不需要手写库、登记文件或 `session.json`。
2. 核对选中的连接名称，填写提供方、接口根地址和默认模型。使用 HTTPS；本机服务可用 HTTP。接口地址不含密钥、用户名密码、查询参数或 `/chat/completions`。模型名以提供方实际支持为准。
3. 在“密钥处理”选择“保存或替换密钥”，输入新密钥后保存；不需要密钥的本机服务可保留未保存状态。密钥不回显、不存浏览器草稿，保存后输入框清空。
4. “保留当前密钥设置”只用于相同提供方与接口。修改这两项时，必须重新输入该接口的密钥，或选择“停用保存的密钥”；程序不会把旧接口的密钥隐含交给新接口。停用后若提示仍有旧密钥，可在停止且确认归还后点击“清理旧密钥”。
5. 保存后重新核对“指挥官风格”显示的连接与“当前有效模型”。连接面板选中的连接可以与当前指挥官所用连接不同；不要误改另一条连接。连接的默认模型与指挥官专用模型不同，专用模型非空时会优先采用。
6. 配置与风格保存会使旧预检失效。保存风格后还要分别观察宿主应用回执和模型消费回执；“已保存”不代表模型已经采用。

“已读取当前本机配置”仅表示本机读取成功。凭据状态只检查是否已保存，不证明密钥有效、远端可用或模型请求成功。正在运行、停止未完成或归还未知时，不允许修改连接。

### 重查与未完成保存的恢复

出现“保存结果未知”时，先点“重新查询连接”，不要连续重复提交。若显示“核对未完成的保存”，使用该按钮核对：程序会恢复已明确写入的版本，或取消尚未应用的更新，并保留原有风格。核对成功后重新检查配置和对局。

本机配置尚未核验或正在核对时，检查、启动与自动等待暂不可用；此前已开启的自动等待会取消。恢复就绪不会自动继续等待或继承旧检查结果，需要重新检查，再由你启动。观察已有运行、请求停止和诊断仍可使用。

若来源已变化、损坏或恢复仍失败，保留现场与诊断交维护者处理；不要通过手改 JSON、替换密钥文件或忽略提示来解除限制。查询、观察旧运行与停止路径仍应优先保留。

### 发现、检查和启动

1. 先由维护者准备当前版本的受信运行组件、发现配置及匹配游戏包。本机当前资格范围是 RA3 1.12、TemplePrime、P3 苏军和已核验出生位置；其他地图、阵营或布局不保证可接入。
2. 正常启动游戏并进入受支持的对局。在客户端点“发现游戏 / 准备下一局”，选择候选，再点“准备所选对局”。这些步骤不等于启动指挥官；无需编辑会话文件。
3. 保存风格后点“检查对局”。检查通过且未过期，才可点“启动指挥官”；配置或会话变化后必须重查。无游戏、暂停、不支持的场景或未确认归还都会保持拒绝，不应反复点启动。
4. 也可选“进入对局后自动启动”，在五分钟等待期间发现、准备并检查，通过后提交一次启动；可随时取消等待。送达未知时只查询原运行，不会自动重发启动。

如果提示风格说明装不下，缩短“补充要求”后保存并重新检查；大量引号和反斜杠也会占用编码容量。新候选会在接管前做容量预检，每轮真实请求仍须满足输入上限。预检通过不保证任意后续战况都能装入请求，也不表示远端模型已经可用。

### 观察、停止、诊断与下一局

观察“当前目标 / 当前阶段 / 最近观测结果 / 保持或调整”。模型方案被接受、原生回执、预算采用和实际战略效果分别记录，不能把它们合称成功。旧局与过期记录会标为最后保存的观测，不代表当前资金或战况。

指挥官只判断高层意图，具体建筑、落点、顺序、兵种、数量与所有单位操作由原生 AI 自主决定。本机已验收的Native5 v9提供进攻、防守、集结、撤退、增援、侦察、扩张、三类预算偏好，以及推进／暂缓建设、生产意图；本局可用能力以匹配候选的预检和目录为准，十四入口的联通与完整本机流程已按本期范围验收；原生采用与任务成功仍须分开。

建设／生产意图作用于原生调度管理器，不等于禁止整局所有建设或生产。开局调度、已经提交的原生工作及其他原生规则可能继续运行。扩张意图可能处于等待，也可能只观测到原生任务或成员移动，不能据此宣布基地已建成。预算偏好、原生采用、已满足状态、任务移动和战略成功分别记录；清除额外偏好不会关闭原生 AI 全部自主工作。

结束时点“请求停止”，持续查询直到“控制归还”收到独立验证。“宿主已停止”“需要处理”或“结算候选”本身都不是归还证明，也不能独立证明胜负。关闭窗口不等于停止；重开后用“恢复观察已有宿主”查询原运行，不要重复启动。

采用新停止关口的Native5候选区分三个阶段：请求停止、停止记录提交生效、独立核验控制归还。请求停止时，已经接纳的指令批次可能先完成；停止记录提交后不再接纳新的指令批次、接管或模型请求。先前已接纳的模型请求可能完成返回，但仍须经过后续停止检查，不能因此继续派发。界面尚在等待或归还未知时继续查询原运行，不把点击按钮或单个回执当成全部停止完成。该关口已通过独立跨进程检查，普通客户端及已定义异常恢复另有实机核验，详见最终报告。

若显示“宿主意外结束”，保留原运行，点击“请求停止”并持续查询。身份记录和现场证据完整时，当前恢复通道可只读核验控制归还；成功后界面会明确显示归还，并开放准备下一局。丢失的当前策略、宿主内存状态和未确认的送达结果仍保留为未知，不会重新发送旧指令。证据缺失或场景变化而无法核验时，状态继续保持未知，保留诊断交维护者处理，不手改文件解除限制。确认归还后，正常退出游戏并重新打开，再发现和准备新对局；同一游戏进程不会因此获得再次接入权限。

需要排查时点“下载脱敏诊断”。下载失败可再次导出，不会重启指挥官。诊断对应注明的运行/会话；新对局不会继承上局的应用或模型回执。诊断中的导出时软件观察与本次运行的冻结版本清单各有范围，不能互相替代。

Native5候选现可从脱敏诊断生成离线过程回放。本机[启动前取消示例](../../reports/native5-early-cancel-timeline-root-20261030-v2/macro-timeline.html)来自真实下载，仅有“最后保存的长期战略”和“宿主停止新增宏观指挥”两条记录，已通过自动播放、暂停、继续及跳转检查。它是记录时间线，未记录单位动画；末尾不足一秒的留白不代表额外观测。三局自然过程数据、首局实际播放及原生录像归档已核验，旧时间线或录像不自动证明新候选可完整复现外部指挥。该示例为本机运行产物，未承诺随源码或安装包分发。

归还核验通过后，正常退出并重新打开游戏，再发现、准备、检查新的受支持对局。当前用过指挥通道的同一游戏进程不支持再次接入；“准备下一局”不会解除这一限制。

## 浏览器离线演示（以下六工作区说明）

适用范围：在浏览器打开开发预览，顶端显示“离线演示”。下面的本机备战、指挥风格、电台素材与离线演练不会调用真实模型或游戏；请勿与前面的 Windows 原生流程混用。

## 1. 准备下一局

在“战前备战”填写地图计划、选择阵营、队友 / 对手关系和 Agent 玩家索引，再配置三种独立资源项：

| 项目 | 含义 |
| --- | --- |
| 游戏初始资金 | 下一局希望使用的开局规则；快捷金额是本机草案，不代表游戏已支持或采用 |
| Agent 生产总支出上限 | 计划交给 Agent 调度的累计生产额度，不会增加开局资金 |
| 资源保留底线 | 希望生产后仍保留的资源，实际派单时还须宿主重新检查 |

点击“保存本机方案”后可重开恢复；导出 JSON 可供讨论或后续适配器接线使用，文件明确标为计划，不是游戏设置、真实连接库或执行命令。未保存的修改在本窗口切页后保留。当前“游戏实际初始资金”仍为未知，请在游戏大厅手动设置和确认。

## 2. 塑造指挥官

在“指挥官工坊”选取档案或新增指挥官，先选稳健经营、均衡应变、主动施压、侧翼游击四个打法预设，再用五档控件调节进攻时机、风险承受、经济投入、侦察积极和追击尺度。

每档都有行为说明，“开局准备 / 受到突袭 / 取得优势”三张卡随设置更新。这是配置解释，不花费模型请求，也不是实际战局推演。补充指挥偏好独立保留，不随预设覆盖；角色与打法也不因更换模型连接而改变。

保存指挥方案后可重开恢复。高级设置可修改模型连接或覆盖模型；“查看宿主适配草案”可查看、复制对应现有三类人格和生成偏好摘要。复制与保存都没有把偏好下发给真实模型或宿主。五档数值是相对偏好，不是实力、胜率或必然行动。

## 3. 为电台准备素材

在“战场电台”管理当前指挥官的通讯素材。可以先试听内置字幕，也可以填写素材名称、对应战况和字幕，再选择本地视频或音频导入；不选择文件则添加一条字幕通讯。

- 支持开局问候、危机提醒、重大损失、成功解围、胜利回应、失利关怀六种战况分类。
- 单条媒体不超过 32 MiB / 90 秒，每位指挥官最多 24 条自定义素材、媒体合计 128 MiB，内置示例字幕不计入条数。媒体是否可解码取决于浏览器或系统 WebView，编码不支持时会提示。
- “试听”直接检查该素材；“事件演练”模拟战况触发，遵守优先级、同类事件冷却与过期规则，不会向局内电台发送内容。
- 可选择安静、标准、活跃频率，调整音量、静音或仅字幕，再保存通讯偏好。安静模式略过开场和成功解围氛围通讯；高优先级事件可打断低优先级内容，危机反转会丢弃过期庆祝。
- 切页或窗口不可见时暂停媒体并清理排队；切换指挥官或会话后不会沿用上一场的通讯队列。媒体失败可显示已填写字幕，不影响演练控制。

素材和通讯偏好存储于当前 origin 的 IndexedDB，不上传远端；档案和备战计划存储于 localStorage。`localhost`、`127.0.0.1`、不同端口 / 协议以及 Tauri 原生窗口的数据独立，不会自动共享。清除网站数据会清除对应素材，原始视频请自行保留。存储失败时界面会说明仅在窗口保留，不能当作永久保存。

## 4. 体验离线指挥流程

先保存备战、指挥官和连接草稿，再回“作战中心”检查演示环境，通过后 20 秒内开始。若要查看异常路径，到“演练与记录”选择无游戏、会话过期或能力检查失败场景。

观察模拟阶段、当前任务和反馈，再点击停止并确认；先显示等待收尾，收到演示回执后才显示已停止。暂停观察与停止演练是两个操作。检查 / 运行 / 收尾期间执行相关配置锁定；编辑备战或档案会让原检查失效，须重新检查。

模型连接页只检查格式，不发真实请求，也不保存真实 API Key。演练使用预设数据，没有扫描游戏或派发游戏命令。

## 浏览器演示与真实入口的区别
