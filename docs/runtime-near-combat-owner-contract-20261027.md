# 近场战斗组合控制器与原生接入边界

本合同对应开发中的 `near_combat.h`、`near_target.h`、`near_owner.h`。它们尚未进入活动 DLL、发布 ABI、candidate13 或能力目录，没有实机攻击授权。完整 G0–G8 目标仍为 active。

## 已实现的执行组合

`Owner` 包装现有 `Controller` 和原始移动 IO，不复制其 SDK、Stop3、回家、恢复姿态或控制归还算法。Reserve 的实际 `remember_home` 样本提供私有起点、原始起始帧/时钟、姿态与外来命令 epoch；已经实际到达 Holding 的同一租约才能准备近场任务。没有第二次 Borrow，没有重新建立原点或延长 900 帧/120 秒总期限。

近场输入为不可变的 command/task/lease/actor、私有目标 key、全局序号、工作期限和原始租约期限；撤回是另外一份预先明确的 ReturnHome 命令，有自己的 ID、后续序号与期限。两种命令共同检查身份和序号，不能借不同路由重用原命令 ID。近场尚在执行时不允许另一路运动命令插入。

近场准备与等待伤害时，由近场控制器观察实际状态，原移动控制器不再按 Holding 要求“仍然 Stop”。确认撤回命令后，原移动控制器恢复 ReturnBraking → Returning → HomeBraking → Restoring → Releasing；不重新 Reserve，也不跳过当前地面、私有原点空位或 Stop3 检查。近场效果、实际回家、恢复姿态和控制归还分开记录。

暂停时，真实 paused 样本仍进入原控制器的观察分支以维持 watchdog；该分支在任何游戏 SDK 行为及 Holding 检查前返回。没有伪造 settled 状态。近场时钟也继续累计，已过期任务恢复后仅提交原定撤回。显式模拟的 30 秒暂停已覆盖准备前和攻击后两种情况，但尚无实机暂停证据。

如果攻击或原控制器回撤交付未知，两层均保留 held 并停止自动重试。现阶段组合层没有新的独立恢复接口；需要后续明确合同和原生静止证据，不能因旧移动层有恢复操作就直接借用。原控制器已确认的同步归还回执可以先于下一次观察；之后原生 AI 已重编队或出现后续演员 incarnation，不会覆盖原回执。

## 目标与伤害

目标读取器只支持受审计的 Conscript 类型，默认模板策略拒绝。两次同帧读取都要验证完整原生视野足迹、敌我关系、存活列表、元组身份、地面与非容器状态；观察者视野、仅中心点可见、被遮罩足迹、未知默认视野不提供目标。失败返回空样本，不输出旧 HP 或坐标。

注册表仅接受读取器封装的 VisiblePair，目标 key 不复用，最多保留 1,024 个记录，满时拒绝而不驱逐。丢失视野会退休旧 key，重新可见需要新封装证据与新 key/incarnation。incarnation 是宿主观察句柄，不是声称的引擎出生代号。

控制器要求任务射击与伤害显式关联，校验命令、演员、目标、原租约、射击/伤害时钟、可见性前后、伤害来源和 HP 差。来源 object ID 或 HP 下降单独不足。当前这些射击关联仍来自显式模拟 IO；真实钩子尚未生产这些证据。

## 当前原生二进制审计

`audit_near_native.py` 只读取 SHA256 为 `ec230c6ae1eaee30b0b4fa6ba29d417c974ecae46d6715dfbe786a815935c165` 的游戏文件，保存 16 项入口/相对调用字节核验和 9 段反汇编；它不打开游戏进程，也不授予模板或调用权限。

- 正常攻击 facade `0x572280` 构造 opcode 11，目标指针在命令 `+0x14`，请求次数在 `+0x44`。
- 原生 copy `0x830220` 将目标指针转换为 object ID，仍存于 `+0x14`，请求次数转入存储槽 `+0x48`。不能沿用 Move 的“目标字段为零”或完整指针相等假设。
- unpack `0x830320` 把 object ID 解析回当前指针。后续钩子需要再次核对原身份/视野，不能把曾经复制过的指针当作永久授权。
- 正常方法 `0x785d20` 调用私有攻击 `0x76e690`，实际返回调用点为 `0x785dd0`；后者把请求次数写到当时选中的武器条目 `+0x24`。
- 请求参数为 1、当时计数写入 1、实际发射数量、任务命中是不同事实。历史实验出现过请求 1 而后来观察到无限计数；原因未在本轮确定，不能推断正常 SDK 的所有路径必然忽略次数。

当前部署的 hooks 对持有单位的攻击仍按外来命令处理。其后另写了开发中的严格攻击链、正常 Stop 对待发攻击的封装替换证明，以及 15 处钩子的独立原生观察器；见[原生接入合同](runtime-near-native-lineage-contract-20261027.md)。这些代码尚未进入发布包，准入默认拒绝。后续仍需独立武器读取、实际射击/伤害链与新 ABI/工厂；不能扩大 source0 白名单、直接调用 trampoline、跳过原生入口或用新布尔字段冒充实机证据。

## 验证范围

当前 47 组 C++ 回放为近场控制 15、目标读取 11、组合控制 9、攻击归属及取消 12；在真正 x64 MSVC 与 x86 GCC 分别执行，共 94 次组执行。另有 3 个未安装 Win32 观察器边界组和原 51 组测试体对 NearMoveLineage 的独立 x86 回归。99 项运行时 Python 检查包含实际编译与回放，并核对活动 v1 的所有原始输入/输出哈希保持不变。它们不提供实机攻击证明。

首个离线快照曾把 x86 产物标成 x64；原快照与失败保留，独立纠正记录为 `reports/native-near-combat-architecture-correction-20261027.json`。随后快照使用真正的 x64 编译器并直接检查产物架构。本轮所有代码都晚于 candidate13 生命周期实测，不反记为该场已执行。
