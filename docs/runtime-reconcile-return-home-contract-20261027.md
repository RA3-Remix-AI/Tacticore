## 新能力的边界

新增具名意图`reconcile_return_home`，使用新的command/request UUID和全局序号，明确引用原uncertain命令。它只做原私有home的第一次安全返回，然后恢复姿态和归还；不恢复原任务、不完成旧Hold、不接受模型给出的替代home，不给未知原命令补造成功。

准入必须同时证明：

1. 原未知动作确为本lease的Commit/MoveHold，身份、task、lease、绑定和原账本相符。不能只检查`current_.operation`：现有控制器的`current_`来自Reserve，MoveHold仅更新目标和驻留参数；需查原始已接受命令与当前receipt的对应关系。
2. 当前SDK Move计数恰为1，即只有原外出Move，且独立的`home_move_attempted_`必须为false。SDK计数不记录NotSent，因此该独立标记在IO前设置，连此前被IO拒绝的home尝试也禁止再派。旧home已尝试、原意图为ReturnHome、或前一次恢复回家已尝试过，全部拒绝这项新能力；只能继续原有明确的释放恢复流程。
3. 同一actor仍由script team持有、存活且接地；四个新静止帧、当前foreign epoch一致、配对96字节空命令槽、状态机反向链接及原witness静止检查全部通过。source2停止状态仅是新命令前置，不是本控制器Stop3。
4. home仍是Borrow前捕获的私有原点。新请求不能更换home或续工作租约。当前位置到home的安全返回范围初定不超过现有原生300上限，原height delta2不变；此更长安全撤回范围必须有独立实机证据，不能从40单位外出校准推断。
