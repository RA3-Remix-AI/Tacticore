# Windows beta：rc06 失败与独立修复

目标版本为 `v0.1.0-beta.1`。本页记录候选修复，不授予实机或公开发布资格。指挥官仍只负责高层意图，原生 AI 负责所有具体建造、生产和单位操作。

## 已有安装与失败证据

rc06 的每用户 NSIS 安装、运行文件和补充第三方声明核对、首次游戏/Mod 选择、配置保存及普通客户端重开已完成。游戏从经过摘要验证的 `RA3_1.12.game` 及固定基础配置启动；新 PID、原始创建时间和实际 TemplePrime/P3 苏联/P4 原生 AI 身份绑定已验证。

rc06 两次 Host 启动都被 `Native6ObservationUnavailable / native6_callback_not_completed` 拦下，模型请求和战略命令均为零。第二次只读追踪再次复现，4 个样本看到已完成回调，整个约 297 毫秒期间回调序号增加 12。两次均按原合同完整 STOP、独立归还，再核验 Game/Host/helper 结束。故障原件、两个 `fault` 历史及各自归还证明保留，不补算正式通过。

原件位于唯一实机控制者的 `acceptance/native6-beta1-rc06-L01-20261031-v1` 与 `acceptance/native6-beta1-rc06-L01-trace-20261031-v1`。这些是本机独立证据目录，不会随安装器分发。

## 回调调度

原 helper 在准备和持续运行期间每 25 毫秒投递一次唤醒，原生 watchdog 又每 100 毫秒投递。准备期持续哈希大量持锁输入时会积压消息；临时启动 hook 和随后安装的自有 hook 也可能处理同一消息。

修复只改变唤醒调度：helper 只投递一个启动消息；自有 hook 和 watchdog 就绪后卸下临时 hook。原生 watchdog 保留 100 毫秒周期，首轮准备及回调完成前不开始自唤醒；此后至多持有一个待处理或执行中的私有票据。回调必须原子领取当前票据才能执行，旧票据、重复 hook 和同票据嵌套不执行 `tick`；发送失败可重新排队。

共享 ABI、所有持锁文件检查、游戏身份检查、命令及未知结果逻辑未改变；观测窗口仍为 250 毫秒／2 帧。调度修复的实际活性与 STOP/到期/心跳丢失归还仍须重新实机验收。

## 有历史会话后的升级

rc06 已产生两个实际 Host 行，不能再通过“从未运行”的空账本条件升级。新的被动历史适配器只识别 rc06 的确定软件身份：manifest `66a966191d56c5d6d31750c0a90288e458d6a0567590fd031ddb3e9258664a25` 与 native source closure `c1df3f59cf08ee332263230ea61d46e39a959b2abd9b6a1a96cf0d992b7d0da2`。

适配器执行当前受信验证器的纯回放函数，以旧软件摘要及比较用安装路径重算原完整证明；不导入旧代码、不运行旧 SDK、不采集新归还、不改变活动模块全局值、不赋予旧局重接权限。未知旧版本、源快照变化、验证器字节变化和不完整归还仍拒绝。

迁移持有两个原始 SQLite 库的写入排他预留，检查跨库 run 与 binding 一致，并在锁内用只读连接重新验证所有会话的完整归还、Host 结束及 Game 退出。它保留旧配置、描述符和启动记录原字节，写入新的版本化配置，最后原子替换发现策略；不删除或改写 Host、命令、事件与未知交付历史。未决控制权、缺库或无法核验的历史不能升级。

## 当前验证与剩余门槛

- Python 相关回归 66/66，包含历史版本拒绝、源/证明变化拒绝、两库锁内重验、失败中断恢复和历史行保持。
- `native-ai/tests/native6_wake_schedule.cpp` 使用实际新原生源码和假投递函数，x86 编译及八类票据反例通过；未启动 Game、未读游戏内存、未发原生命令。
- 普通 Windows 进程中的纯文件回放已重算 rc06 两次真实完整归还：原两库 `mode=ro` / `query_only`、文件摘要不变、仍为两个 `fault`、活动验证器全局值不变。
- 独立复核另以真实归还原件验证七项反例均拒绝，包含残留 Hook、未决交付和重算摘要后的损坏日志。打包后的首用／历史回归 27/27，全部 3,456 个可执行输入持续持锁，6,912 次写入／删除句柄打开均被拒绝。
