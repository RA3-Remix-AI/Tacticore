# 弈核 Tacticore Beta 3 使用说明

当前为验收候选：同一 V11 候选的三局新自然验收已通过 3/3；P1 扩张已通过“有效期内活动 → 历史效果与到期结果 → 后轮真实接受判断”的有界闭环，新普通账户的安装、首次配置和正常重开也已通过，既定 P0/P1 及 F01–F07 按有界标准完成。扩张活动不代表任务完成，同一有效期内直接接受新意图的更强检查未通过。当前身份与进度见 [交付计划](windows-beta3-delivery-plan-20261104.md)。安装包位于 `C:\tacticore-beta3-release-v3k\Tacticore_0.1.0-beta.3_x64-setup.exe`，尚未发布新的公开下载版本。

## 开始前

准备已核验的红警 3 1.12 繁中配置、兼容 Mod 和可用的模型连接。安装包不包含游戏、Mod BIG 或模型服务额度。当前支持 TemplePrime（原始神庙）和 InfinityIsle（无限岛），受控席位为 P3 苏军、出生位置 2，对手为 P4 原生电脑。其他地图、受控阵营或位置尚未验证。

升级前，先停止旧指挥并等到独立控制归还确认，再正常退出游戏和客户端。运行安装包，在原目录添加／重新安装组件。安装完成后重新打开客户端；已有配置和运行记录应保留。

## 配置与开局

1. 在“战前备战”选择本机游戏和 Mod，完成环境核验。
2. 在“模型连接”设置服务、模型和密钥。配置已保存或本机核验通过，不代表远端本次一定可用；真实调用状态在作战中心查看。
3. 在“指挥官工坊”选择普通风格并保存。偏好用于影响高层判断，不会授予指定建筑、兵种或单位操作权限。修改后在下一次启动生效。
4. 通过“启动游戏”进入原生“对战 → 遭遇战”。选择上述地图，人类设为观察者；受控中等 AI 选择 MACRO PROBE P3、苏军、出生位置 2；P4 使用中等原生 AI，可随机阵营与指挥官；其他位置关闭、无组队、初始资金 10000、关闭宝箱。
5. 游戏开始后进入“作战中心”，使用“发现游戏／准备下一局”，然后检查与启动；也可使用“进入对局后自动启动”，最多等待五分钟，可取消。无需手改会话文件。

## 观察指挥

作战中心分别显示“模型决定做什么”“原生如何响应”和“结果与后续判断”。模型可以选择进退、侦察、扩张和建设／生产的高层意图，保持或调整战略，并公开原因。具体建筑、落点、顺序、兵种、数量、队列及全部单位操作由原生 AI 决定。

“模型已返回”不等于方案被接受；“原生已接受”不等于任务完成。预算采用表示额外投入偏好，移动表示有界活动；等待、拒绝、到期或无效果均可能是正常反馈。建设／生产推进也可能只确认原生调度本来已经开启。防守目前有等待／无效果反馈证据，不能据此承诺完成防守。

调用摘要区分等待响应、返回、失败及取消。它不区分网络等待与模型推理。遇到连接故障，保留错误和本地回退记录，核对连接后再继续观察；不要把一次 HTTP 成功或一次响应当成持续服务保证。

## 停止、诊断和下一局

需要结束指挥时点击右上角“请求停止”，等到“已收到独立控制归还验证”。停止请求、进程退出、结算候选和控制归还是不同事实。状态过期或未确认归还时，保留诊断并继续核对，不以强行关闭游戏代替归还验证。

在“运行记录”查看该局过程并导出脱敏诊断。自然结算后保存原生录像，再从原生菜单正常退出游戏。下一局须使用新游戏进程，再发现、检查和启动；同一已停止的游戏进程不支持重新接管。归还后原生 AI 可以继续自主运行。

## 回放与限制

诊断包含运行身份、模型消费、意图、执行反馈和生命周期事件。交付中的离线过程页可浏览已导出的全部事件，不连接模型或控制游戏。独立归还仍由原始完整核验材料证明。

原生 RA3Replay 用于查看原生游戏过程，不包含完整模型推理。已有录像在默认速度下出现比原局提前结束或统计过程不一致的缺陷，根因和修复尚未完成；不能依靠录像单独证明外部战略状态忠实重现或模型独占战果。请与诊断、原始自然结果和过程记录交叉查看。

本候选不承诺提高胜率、原生任务每次完成、模型服务持续可用或跨机器兼容。已在当前电脑的新普通账户验证空白首用与重开，使用该机器已有的 WebView2、游戏和已核验兼容 Mod；全新 Windows 机器及其他依赖组合尚未验证。
