# 弈核宏观指挥功能完善计划

自主战略与持续调整 完整客户端会话流程 建造科技与兵种扩展

2026年10月28日，计划版本1.0，状态：待实施。

## 一 总体目标和实施边界

下一阶段建设一套能够日常反复使用的本机宏观指挥系统。用户从客户端配置指挥官、准备对局并启动，模型根据合法可见战况维持战略、调整资源和部队任务，原生AI执行建造、生产和单位操作，战后可以解释哪些意图被采用、哪些没有生效。

本计划以2026年10月28日已通过的本机有界G0–G8为基线，提出新增功能及验收要求。当前版本是schema9；完整自然对局证据合法复用旧schema7，而新增集结、撤退和增援采用定向场景验证。因此本轮新增的首要证据，是当前候选版本使用普通风格、无需分时指令的完整自然对局。计划尚未启动实施，不改写既有完成结论。

| 工作线 | 本轮目标 | 最终交付 |
| --- | --- | --- |
| A 自主战略 | 连续维持目标，按战况改派，减少无效重复 | 战略状态与决策合同、重放集、当前版本自然对局报告 |
| B 客户端会话 | 配置到下一局均可由普通用户操作 | 受信会话发现与注册、清晰状态、故障恢复及诊断流程 |
| C 能力扩展 | 逐项增加苏军建造、科技和地面兵种 | 原生消费者、真实效果反馈、分项能力清单与回归包 |

### 当前可复用的成果

保留真实模型连接、配置修订、持续记忆、合法视野、权威命令账本、原生任务消费者、独立释放和脱敏时间线。原始风格已恢复为修订21。新增能力继续通过可信能力包逐项授予，模型提示词、界面选项和动作名称本身不授予执行权限。

### 本期范围

本期沿用RA3 1.12、TemplePrime、P3苏军及当前已资格化出生位置。会话发现须识别并拒绝尚未支持的地图、阵营和位置；另一出生位置作为后续独立资格。优先普通电力、兵营、战车工厂、矿场、已具资格的超级反应堆、作战实验室及常用地面单位。新地图、新阵营、海空完整体系、游戏电台和跨机器安装留作后续里程碑。

模型始终只决定宏观目标和受支持的资源、生产及部队任务。选兵、寻路、阵型、局部目标、开火和技能由原生AI负责。已有1500秒宿主上限、原生看门狗和同进程停止后不可重新接入的限制，必须在会话设计中显式处理。

## 二 三条工作线的共同架构

共同流程为：客户端配置与受信会话绑定 → 合法观测和能力目录 → 战略状态与模型计划 → 合同及预算校验 → 原生高层消费者 → 效果反馈与账本 → 下一轮决策和客户端展示。三条工作线共享同一会话身份、动作语义、生命周期和证据编号。

| 共享合同 | 本轮必须明确的内容 |
| --- | --- |
| 能力目录 | 动作、原生消费者、目标选择方式、前置条件、数量单位、并发冲突、最大时限、实际可观测效果和未知项 |
| 战略状态 | 当前目标、依据的公开事实、预期观测变化、保持条件、改派条件、资源分配和最近效果摘要 |
| 执行回执 | 提出、校验通过、原生接受、执行中、有界效果、未达目标、取消、到期、被替换和结果未知 |
| 会话身份 | 游戏PID和原始创建时间、地图及阵营、玩家身份、原生包和构建哈希、配置修订、运行编号 |
| 时间与额度 | 游戏时间用于计划有效期和情报年龄；墙钟用于网络超时、失联和运行上限；两者不能互相代替 |

### 先冻结数据含义 再接执行

当前13个原生flag均有已授予用途。M0先确定新增动作采用扩展flag还是带参数的领域协议，并为传输、清理、观测和验收器建立一致的新版本。禁止复用已有撤退或增援flag偷偷改变语义；旧资格只有在消费者语义等价得到核验后才能继承。

优先增加纯数据合同、合法观测和离线重放，使用冻结样本核对各层对同一字段的解释，再接入原生消费者。当前同一计划允许的工作动作与预算组合限制先保留；多目标战略通过调度不同决策窗口实现，避免一开始同时开放多个相互覆盖的工作动作。

### 不可放松的约束

- 未授权动作、旧局、旧配置、过期情报和迟到响应不得派发；停止后不得产生新模型请求或宏观命令。
- 结果未知时保留未决记录并核对，禁止因为没有收到ACK就生成新命令盲重试。
- 敌方信息只来自己方合法视野。自身对象存在、可招募、已完工和可生产必须分别表达。
- 模型输入继续执行16KiB边界；新增能力和反馈必须有大小测试，优先保留当前目标、关键事实、许可与失败原因。
- 版本升级使用新的构建和证据目录，保留已发布基线及全部失败样本。

前端、策略和原生适配器只消费经过版本校验的公共合同。若某项原生事实暂时无法可靠读取，应保留unknown并限制依赖它的能力，不能由界面或模型猜测补齐。

## 三 自主战略的行为和状态设计

战略层应回答当前最重要的目标、为什么保持它、什么变化会触发调整，以及上一次意图实际改变了什么。沿用已有记忆和结构化计划，增加独立于单条计划有效期的战略状态；单次宏观计划到期后，长期目标和已核实结果仍应保留。

### 战略状态的最小字段

建议新增strategy_id、objective、phase、public_fact_refs、expected_observation、continue_conditions、replan_conditions、resource_priorities、last_outcome及updated_game_seconds。字段记录可审阅的目标和事实摘要，不保存模型隐藏思维过程。没有新事实时可以维持策略并明确等待原因。

| 战况 | 可选宏观调整 | 必须具备的依据 |
| --- | --- | --- |
| 电力或资源受限 | 补电、经济投入、延后非必要科技 | 可靠的己方电力、资源、队列和前置观测 |
| 己方设施受威胁 | 防守、增援或暂缓前推 | 合法接触、己方设施和可用部队摘要 |
| 兵力不足或受损 | 调整构成、补充、集结或撤退 | 己方兵力变化、原生任务效果及可招募性边界 |
| 有进攻机会 | 在已授予区域前推并继续侦察 | 未过期的己方视野、原生任务条件和投入余量 |
| 连续无效果 | 保留原生自主、改变方案或等待条件 | 同动作同目标的近期结果、阻碍与事实变化 |

### 决策频率和切换控制

保留单个未完成模型请求和单一派发入口。普通决策使用可配置的评估间隔，并以离线重放调节；重大威胁、生产者丢失和可信任务失败可提出提前重评，但仍受网络请求频率、身份和预算限制。普通策略设置最短保持时间，紧急情况允许提前退出，避免每轮在进攻和撤退之间摆动。

开始执行前再次读取最新能力与前置条件。旧响应若已失去依据则拒绝或重新评估，不能为了维持计划而使用已失效目标。网络异常时停止新增模型指挥，原生AI按既定边界继续工作，并向客户端显示真实原因。

## 四 自主战略的实施任务和验收

| 任务 | 实现内容 | 完成标准 |
| --- | --- | --- |
| A01 战略记忆 | 从既有BattleAgent记忆中分离长期目标与短期计划，保留效果和失败摘要 | 计划到期或上下文压缩后，目标、阻碍和已核实结果仍进入后续请求 |
| A02 计划调度 | 按优先级、当前能力、资源和任务冲突选择下一工作动作 | 低资源、威胁、科技缺失等重放场景选择合法动作或明确等待 |
| A03 重复处理 | 按动作、目标、数量及关键事实标识相似意图，加入失败冷却 | 相同阻碍不消耗式重复派发；条件改变后可以重新决策 |
| A04 反馈闭环 | 关联计划、原生任务、效果和下一轮策略，记录改派依据 | 每条被认定有效的调整均可追到实际观测及后续真实响应 |
| A05 自主整局 | 使用普通风格连续自然对战，记录失败及恢复 | 三局均绑定同一候选构建，无分时覆盖提示、无脚本替模型选动作 |

### 重复指令和任务切换的处理

区分传输幂等、工作动作续期和战略重试。相同命令编号不能重复执行；已失效的命令不能当作续期；只有资源、前置、目标或兵力条件有变化时，才允许对相同失败意图重新评估。已接受但效果未知的任务先查询账本和原生状态，不创建替代命令掩盖未知。

无效果次数、普通保持时间和冷却时间均作为候选参数记录，先用固定重放集比较，再进实机。不能只靠屏蔽所有重复来提高指标，因为生产补充、持续防守和有依据的任务续期本身可能合理。

### 验证安排

离线覆盖资源不足、过期敌情、开局前置未满足、威胁增加、目标失效、连续无效果、计划到期、迟到回复和停止。实机先用现有已授予能力跑一次短窗，确认记忆与改派回传，再运行当前候选版三局自然结算。某局不具备合理撤退或科技机会时，不强迫它覆盖对应动作；能力分项资格与自然局综合表现分别验收。

报告记录合法计划比例、被拒绝原因、相同阻碍下的重复次数、有效改派链、请求和反馈延迟、未知结果及停止行为。三局作为功能试运行样本，不能据此宣称胜率提升。A线完成要求所有规定功能场景通过，失败或中断的正式局须保留并在修复后补齐三局有效样本。

## 五 完整客户端会话流程

普通使用路径为：选择指挥官与模型 → 保存风格 → 发现游戏和对局 → 只读预检 → 开局自动启动或手动启动 → 查看状态与反馈 → 停止或自然结束 → 确认归还 → 复盘与准备下一局。普通路径不要求用户编辑session文件、调用CLI注册或理解原生epoch。

| 用户看到的状态 | 允许操作 | 后台必须核验 |
| --- | --- | --- |
| 未发现游戏 或 等待进入对局 | 保存配置、查看指引、取消等待 | 受支持版本与安装路径，尚未获得执行资格 |
| 对局待核验 | 检查对局、查看缺项 | PID与创建时间、地图、阵营、玩家、包、能力及配置修订 |
| 可以启动 | 手动启动或开局自动启动 | 短期准入凭证仍有效，启动时再次核验 |
| 启动中 或 运行中 | 观察、查询、停止 | 宿主应用回执、真实模型请求状态、原生接受和效果分别展示 |
| 停止中 或 归还待核验 | 查询、导出诊断 | 停止新增请求，处理未决命令并独立核验释放 |
| 已停止 或 已结算 | 复盘、编辑下一局、发现新局 | 释放已确认，旧准入和旧响应不能流入下一局 |

### 受信会话发现和注册

把现有显式CLI引导包装为原生后端受限服务。后端从受信安装与构建清单发现候选进程，只读核验真实身份后创建不可变会话。WebView只传允许的配置标识和操作意图，不能提交任意路径、PID、内存地址或自行构造能力包。发现多个候选时展示可辨认的进程和对局信息，由用户选择后再严格核验。

新一局即使复用了同一游戏PID，也必须重新核对游戏逻辑对象、玩家和地图绑定，生成新会话身份。注册更换采用原子提交；旧运行未归还或有未决命令时阻止切换。客户端启动时重新读取受信注册，减少因配置更新而被迫重开整个应用。

### 用户可以看懂的反馈

主界面展示当前目标、正在等待什么、最近有效反馈、模型连接健康和停止状态。接收响应、原生接受与任务完成分别标记；过期数据带最后更新时间。技术错误码保留在诊断详情，主提示给出具体下一步。

## 六 会话恢复和停止边界

| 事件 | 预期行为 | 验收要点 |
| --- | --- | --- |
| 关闭再开客户端 | 恢复观察正在运行的宿主；宿主按既定策略继续 | 不会启动第二宿主或重复派发，显示当前实际修订 |
| 模型网络失败 | 执行有界退避，保留已知计划和失败；原生AI继续 | 不无限重试，不把失败显示为模型思考或任务完成 |
| 宿主崩溃或失联 | 进入待处理状态，依赖既有心跳和看门狗清理并核验 | 未证明释放前禁止新指挥；未知命令不自动重发 |
| 游戏退出或切换对局 | 旧会话终止，旧请求和准入全部失效 | 旧局回复、同PID新局和过期配置均不能误派 |
| 用户请求停止 | 停止新请求、取消或隔离在途响应、清理宏观意图 | 独立核验标志、hook、lease及未决账本；原生游戏不被强制结束 |
| 下一局 | 发现并核验新会话，保留用户配置并生成新运行 | 完整流程无需手改注册文件或遗留上局状态 |

### 本期恢复的明确范围

优先保证客户端重新打开后恢复观察，以及停止后顺畅准备下一局。当前原生运行时停止后会保留该进程的通道对象，不能再次接入同一epoch。本期默认保留这项限制并提供明确指引；不把界面重新启用启动按钮当作实现恢复。

同局停止后重新指挥作为单独的B06研究项：先设计新epoch的初始化、旧通道终结、租约互斥和未知命令隔离，再做异常退出、PID复用和重复启动测试。只有原生协议与实机证据均通过才开放入口；若未通过，完整版本仍明确要求新会话，不对用户承诺同局恢复。

### 长局与暂停

核对当前1500秒宿主墙钟边界和原生约30分钟看门狗，建立可解释的最大运行时长、心跳失联期限和模型请求超时。需要覆盖更长自然局时，先验证受控续期及停止路径，不能直接取消保护。暂停游戏不产生基于旧战况的新意图；游戏时钟、墙钟、模型迟到年龄均单独测试。

租约检查须匹配原生实际的semaphore对象类型。对象仍存在与lease仍被占用是不同事实；不能把OpenMutex的空返回当作信号量已释放。准入、停止和恢复统一使用经核验的对象类型、原生状态和账本证据。

B线最终通过条件是：完整普通流程通过，反复点击及重复消息幂等，全部异常场景有明确状态和下一步，关闭界面不误停游戏，停止后零新增指挥。诊断仍经客户端实际下载并与原导出核对，不包含连接凭据。

## 七 建造科技和兵种的扩展顺序

先补齐观测和前置条件，再增加原生消费者，最后让模型自主选择。现有buildtech、economyrefinery和build_airfield等动作名称只代表合同中的候选语义，不表示已取得本局执行权限。每个新消费者都需要对应包、构建、原生效果和模型反馈证据。

| 批次 | 建议范围 | 进入模型前的门槛 |
| --- | --- | --- |
| C0 观测基础 | 普通电力、资源、生产者、建造队列、己方建筑和兵力状态 | 身份及时效可靠；存在、完工、供电、可生产和可招募分别表达 |
| C1 基本建造 | 矿场、普通电厂、兵营、战车工厂；保留超级反应堆 | 逐项真实建造管理消费者与原生合法落点，拒绝缺前置和重复超额建造 |
| C2 科技路径 | 超级反应堆、作战实验室及经核验的解锁关系 | 科技设施可运转和实际解锁有原生观测；科技预算比例不能替代升级证明 |
| C3 地面构成 | 已资格化征召兵、高射炮兵、铁锤坦克；候选新增镰刀机甲和牛蛙载具 | 候选模板、生产者、数量及队列消费者逐一验证后，才进入可用目录 |
| C4 综合调度 | 根据合法敌情调整反步兵、防空、装甲和补充构成 | 所有构成选择只能由当前已授予的单位类型与数量组成 |

### 每一项能力的固定交付

登记动作及真实原生消费者，核对输入单位与前置条件，做固定意图短窗试验，保存原生接受、可归属的效果、到期或替换及清理，随后取得真实模型选择和后续反馈。最后才更新可信能力包、客户端支持清单与独立评估。出现任一缺口，保留为未支持或部分观测，不能通过提示词宣告完成。

初始数量沿用已核验的有限选择，不直接开放任意数量。先保证新增队列与取消、替换、生产者丢失处理正确，再增加配额或比例。模型表达构成目标，具体出厂后编组和交战仍交给原生AI。

### 消费者不通时如何处理

每个候选安排有界研究窗口并记录阻断原因。若某建筑或单位没有可证明的原生消费者，该项继续保留为完整扩展的待办；候选版可关闭该项，完整计划不得把换名、静态声明或原生自发行为算作已实现。飞机、海军和特殊技能需另立后续批次。

## 八 建造生产和科技的真实反馈

建立统一效果台账，关联宏观意图、原生队列、己方对象和后续决策。保留原始身份及帧时间；面向模型只投影稳定标识和可用事实。队列接受、施工对象出现、建筑可运转、单位出厂、付款和科技解锁分别记录，避免同一个绿色状态覆盖多个不同事实。

| 事实 | 应取得的证据 | 不得直接推断 |
| --- | --- | --- |
| 新增队列接受 | 意图前后匹配的原生队列、生产者、类型和数量变化 | 单位或建筑已完成、已支付全部成本 |
| 施工对象出现 | 己方对象身份、类型、位置及与队列的关联 | 建筑完工、供电正常或科技可用 |
| 建筑可运转 | 经核验的完工、供电及原生运行条件 | 仅凭HP大于零或队列消失就判定完成 |
| 单位出厂 | 新增己方单位身份和类型、匹配生产链及时间 | 把所有新单位都归因于模型，或认为单位必定可招募 |
| 取消或丢失 | 可信取消回执、原生销毁或生产者变化 | 观测不到就判定取消、摧毁、退款或失败 |
| 科技解锁 | 设施状态及经核验的原生生产许可变化 | 科技账户比例增加就等于科技升级 |

### 预算含义与并发支出

继续区分模型分配比例、原生账户配置、已接受队列的估计成本、真实已付费用和退款。比例相加满足约束不代表实际支出可控。若支付流或原生自主支出尚无法完整观察，界面只显示偏好和已观测下界，不展示未经验证的硬总支出上限。

对宿主可以控制的新增请求建立资源预留，处理多生产者、队列替换和取消；收到可信回执才释放预留。原生AI的并发自行生产与建造单独列出。若不能在派发前可靠限制实际支出，应缩小可执行范围并明确额度语义，不能以原生事后记账冒充前置预算保障。

### 效果归属

使用意图前基线、队列及对象标识、效果窗口和后续命令边界限定贡献。存在原生自主生产或身份关联缺口时，保留“同时观察到”而非独占归因。期限结束后的变化可以作为下一轮战况，不能回填成旧命令在有效期内的成功。

### 三个典型闭环

- 经济补充：模型识别资源压力 → 选择合法矿场建造意图 → 原生建造队列及对象 → 设施实际状态反馈 → 下一轮保持或调整投入。
- 科技推进：模型选择科技设施并保留资源 → 原生接受和施工 → 可靠完工及运行观测 → 实际解锁进入能力目录 → 后续模型选择相应兵种。
- 兵种调整：合法敌情变化 → 选择已经授予的单位与配额 → 原生新增队列 → 出厂或未完成事实 → 后续调整构成和部队任务。

首次验证只改变一个消费者或一个观测层。对新原生包进行逐资产或等价版本审计，更新包哈希与观察器绑定；未证明语义等价时，不复用旧原生效果作为新版本的执行资格。综合自然局最终必须使用同一候选构建，不再用旧版本完整局替代本轮新增要求。

C线完整完成以本期列明的能力逐项结果为准。若一个候选仍受原生接口阻断，阶段报告明确列出缺项和研究下一步，不能宣称全部扩展完成。

### 依赖与关键路径

共享合同稳定 → 受信会话可重复准备 → 新观测及消费者资格 → 策略按最新能力运行 → 冻结构建 → 当前版本三局整局验收。A线可先用旧能力推进；C线每增加一个已验证消费者，立即交给A线做离线组合，避免让策略和客户端等待全部原生研究结束。

## 十一 单客户端排程和并行分工

游戏客户端保持唯一，由主线程统一持有实机执行权。子Agent可以独立分析、实现和重放，但不启动第二游戏、不直接读写活游戏进程、不发原生控制命令、不使用真实连接发模型研究请求。需要实机的任务提交明确试验卡，由主线程按依赖串行执行。

| 执行者 | 可并行任务 | 交接物 |
| --- | --- | --- |
| 主线程 | 原生构建集成、游戏启动、真实模型试验、实际UI和停止验证 | 唯一实机日程、会话与包指纹、实际原始证据及最终合并版本 |
| Agent A | 战略状态、记忆、重规划、重复抑制及离线策略重放 | 策略补丁、公开样本、行为对比和失败场景报告 |
| Agent B | 原生后端受信发现、客户端状态和恢复流程、模拟RPC及界面验证 | 前后端补丁、状态合同、异常用例与可操作界面 |
| Agent C | 原生消费者静态审计、观测和队列台账、能力包及独立验收器 | 消费者证据、观测补丁、短窗试验卡和独立负例 |

### 每次实机窗口的规则

- 试验前冻结唯一构建，明确待证明事实、前置局势、输出目录、最大时限、退出条件和清理步骤。
- 优先执行能区分方案的最小短窗，不用长局替代消费者是否存在、字段是否可靠等基础检查。
- 同包且互不干扰的观察可以合并；相互覆盖的建造、生产与部队意图分别排窗口，不能以并行派单抢占原生状态。
- 停止并独立核验释放后再换任务。当前同epoch不可重接时新开会话，不修改账本或通道来伪造可继续状态。
- 一轮无效果必须先说明score、前置、可招募性、期限及样本缺口，再决定是否重试；不能无界重复同一配置。

### 代码合并和复核

三条工作线使用独立分支或明确文件所有权。共享合同由主线程先合并；Agent不同时改同一运行文件。源文件一旦变化，原实机证据只保留为对应旧版本资格；新候选重新冻结并运行适当回归。独立验收器由非实现者复核，先验证负例能被拒绝，再评估真实试验结果。

日志和界面显示可以并行制作，真实验收计数仍只来自同一局的模型、命令和效果链，不能把影子请求或其他Agent的模拟结果并入实战次数。

## 十二 验收矩阵和最终交付

| 场景组 | 必须覆盖的案例 | 通过依据 |
| --- | --- | --- |

### 发布门槛

旧局误派、停止后新指挥、重复执行未知命令、隐藏敌情泄漏、凭据进入诊断均为零容忍失败。功能质量记录有效改派、无效重复、完成或未知分布以及实际延迟；任何百分比必须给分子、分母和排除规则。模型失败允许按合同处理，不要求每份模型回复有效或每场必胜。

冻结当前候选后执行相关单元与重放测试、原生分项资格、实际UI流程，再串行运行三局自然结算。原始风格至少覆盖一局，其余使用预先记录的普通预设；整局不加入按秒指定动作的验收提示。正式局不通过时保留失败，修复后重跑受影响范围并补足样本。三局不构成胜率或风格因果证明。

### 交付与回退

交付功能清单及未支持项、客户端与原生版本清单、逐项独立报告、三局公开配置和脱敏诊断、关键截图、离线过程回放、原生录像及其限制、安装与使用步骤、模型异常及下一局指引。独立安装作为另一个明确项目，不因本期本机交付自动宣称跨机器可用。
