# 当前近场战斗与自卫接口缺口

本记录承接candidate13生命周期实机，不授予任何新能力。完整目标仍按G4→G6推进；当前客户端的主攻、骚扰、协同保持unsupported。

## 已核对的活动接口

- `tactical/runtime/protocol.h`当前只有Reserve、MoveHold、ReturnHome、停止/查询及独立恢复操作；`Command`没有敌方目标身份合同，`Action`及SDK计数为6项。移动端点不能替代可见敌方目标。
- `tactical/runtime/hooks.cpp`已观察`0x76e690`，签名为thiscall的update、target、shots、source。活动`attack_hook`对持有演员的攻击一律增加foreign epoch；它尚未区分受托攻击或有证据的原生自卫。直接发攻击或白名单放行会破坏现有未知命令保护。
- `tactical/combat-finite/lease.cpp`等历史源码包含一次有限攻击调用及可见目标检查，可用于核对ABI线索；它们不是活动宿主的新执行权限或新的效果证明。旧MF实验目录继续作为历史材料。
- `native_yield.h`的普通让路资格仅限已经验证的Flak精确来源、调用链和state26确认。`043207`是flags1的完整让路/中止/回家分项，不能从该分项推导普通自卫、命中或双兵能力。

## 后续实现必须补齐

1. 将攻击/自卫的目标、己方视野来源与年龄、敌我关系、演员及目标存活/身份、允许调用源和一次交付结果形成明确类型；先做注入式重放。外来或未知来源继续保留unknown。
2. 选择能表达敌方目标及攻击归属的协议演进边界。不能复用移动点、保持帧数或演员字段暗藏目标地址；旧发布包、源快照、协议及已授权移动证据保持可独立复验。
3. 原生调用前再次检查游戏线程、当前视野、双方身份、距离/武器适用性、控制归属和原始总租约。近场效果需攻击调用、伤害/命中归因及实际回撤/归还分别证明；目标HP变化或外来原生伤害不能单独计入模型任务。
4. 单兵近场验证通过后再推进双兵、视野丢失/人工停止/死亡；新能力只登记已证明的范围，然后接模型任务和G6长程战术。

## 同时保留的准备问题

candidate13实付4兵而没有出现可借兵机会；本轮证明了有界等待和正常停止，没有证明重复模型动作的可用性。计划中“生产前已知意图、出厂时有界接管”与“原生池按需借用”的受控比较仍有价值。出厂接管必须有独立的付款、出生和原生未分配证明，并保留原始总持有期限，不能仅因为现有单位难借就放宽source0或无限持有。

该缺口需要原生合同和可控实验解决，不能靠提示词或扩大等待时间替代。
