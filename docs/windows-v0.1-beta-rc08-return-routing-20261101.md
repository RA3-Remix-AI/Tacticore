# rc08：正常 STOP 证明分支与升级保护

rc07 的 L02 实际完成了 GUI STOP 和原完整独立归还：停止提交后无新增指挥，原 final-state、独立归还和日志验证通过。但客户端随后主动进入异常 Host 恢复收集器，在已提交的正常归还旁留下 orphan 文件。旧 reader 按文件存在性选择异常证明，反而拒绝已提交的正常证明，导致下一局入口锁定。原始 mixed 文件、账本和失败结论全部保留。

rc08 以账本中已 `released` 的 `macro-stop` receipt 的合同决定复核分支。正常与未附着合同重算原有全部条件；异常 Host 合同重算原有异常证明。未选择的文件不能改派证明合同，损坏的已提交证明不能借另一分支或重新采集变成通过。未完成 STOP 仍由原恢复收集器处理。

原 `native6_lifecycle.py`、`native6_release.py`、`native6_no_attachment.py`、`native6_orphan_return.py` 及两个依赖的 v5 证明验证器保持原字节。独立正常 reader 的每个原校验语句以 AST 对比确认保留。历史 adapter 只认可确定的 rc06/rc07 软件身份，执行当前验证器纯回放，不导入旧代码、不重接旧 Game、不改写历史账本。Native6 异常 Host 的只读历史状态也按已验证合同投影，不能凭 v5/v6 文件名把正常 STOP 改成异常。

安装器先在自己的私有临时目录提取新版 EXE 和完整受 EXE 编译期摘要约束的 runtime，以新版校验器检查两个原始账本、完整归还和 Game/launcher 全部退出，再替换安装文件。它不执行旧版的缺陷 reader，不接受外部“允许更新”标志。相同版本修复安装时，历史中的原安装根仅用于纯证明比较，不成为导入根或执行授权；原冻结快照、版本摘要及验证器字节仍须匹配。未归还、未知版本、损坏证明或运行中的 Game 均拒绝安装。卸载继续使用当前安装版本的完整维护校验。

离线相关回归 82/82 通过，涵盖证明分支拒绝回退、未完成恢复、完整未附着证明、历史软件身份与源变化、同版本安装根迁移、活动历史及 Game 阻止升级。离线结果不代替实机验收。Native 源码、协议 6 ABI、输入/句柄上限、合法视野及 14 个高层动作边界均未放宽。

rc08 尚需完成打包后的回归、实际保留历史升级与重开、客户端生命周期以及 F01–F07 和同一冻结候选三局自然结算。当前新 beta 正式计数仍为 **0/3**；rc07 的实机反馈与归还仅作原候选证据，不自动计为 rc08 的完成项。没有干净 Windows 虚拟机实测，不宣称已完成该项。
