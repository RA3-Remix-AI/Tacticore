# Tactical bridge experiments

`lease.py --readiness` only reads current session/player/commander and live own-unit identities. It supports verified Soviet Flak and Conscript hashes, independently pins the executable/process start, package SHA, selected personality UUID, owner and native team pools. It does not depend on old heap snapshots.

`lease.py --execute --object-id ID --natural CURRENT_NATURAL_JSON --dx 80 --dy 0` is the narrow live experiment for the orchestrating agent. The current natural build evidence must be restored, have no active callbacks, and contain a matching native queue node/cost and a known caller/ABI on the game window thread. Importing this module never attaches.

Native actions run through WH_GETMESSAGE on that thread. A PINned DLL installs a window-thread timer. A paused match can be armed for at most 60 wall seconds; no SDK action occurs until unpaused. The DLL calls the normal `UNIT_AI_TRANSFER(false)` once, one move of 20–120 world units, then `UNIT_AI_TRANSFER(true)` once after 3 arrival samples, expiry (30–180 logic frames), stop request, or wall deadline. SDK calls are not repeated per frame. The normal return places the unit in the same player's native common pool; it does not recreate the original squad. The timer and mapping remain in the game if the host exits, so a pending return can run when the game resumes. A hung game thread cannot safely be recovered from a worker thread; report it pending/unknown.

Lifecycle checks pin GameLogic, Thing ObjectID, owner, type, AIUpdate and its Thing backpointer, HP, Player/AIPlayer and selected personality. Pause is rechecked on the game thread. A reused or dead unit never receives another SDK call. Per-process mapping permits only one smoke experiment, preventing duplicate execution; this is not yet the persistent task executor.

Five passive hooks preserve native arguments and record Move, Attack, Transfer, AI-manager Add and Remove events. Every record has tag (native/our detach/our move/our return), thread, frame, caller, object owner/team, source and position. Original entry bytes must match exactly. Hook cleanup disables them, verifies all five restored entries, and retains DLL/trampolines until game exit.

The report is written before dispatch and updated while running. Exceptions and unknown dispatch/timeout produce durable failure evidence. Assessment requires one detach/move/return, exact expected Add/Remove manager and callers, preserved owner and temporary script team, observed arrival, normal pool return, restored hooks and no lifecycle/log errors or observed native override. Native reacquisition after return is reported separately using a later team change or observed native Move/Attack; absence of those hooks is not universal proof of no interference.

## Acceptance remains separated

- **raid / recon**: trusted bounded region, real travel and new area coverage, normal AI return; not unlocked by smoke alone.
- **raid / harass_economy**: currently visible economy contact, causal attacks/disruption and normal return; unverified.

- **combined_arms**: at least two distinct roles, disjoint versioned formations, separate role goals and measurable coordinated spacing/timing; simultaneous moves toward a point alone do not pass.

The LLM receives abstract formation/contact IDs, never native addresses. Capabilities stay locked until their separate evidence is reviewed.

The single Conscript short move and normal AI common-pool return have live proof in `primitive-evidence-223317.json`. Its assessment remains not_passed. maxShots0 semantics were not established. New `combat-finite/` uses positive maxShots1 and separately records the selected WeaponEntry limit and ammo changes; `combat-traced/` also captures native hit call stacks. An ammo interval is not a new-order projectile identity. Until same-fire association is proven, the purpose verifier explicitly rejects attack/harass grants even if the diagnostic primitive reports positive shooter/target damage.

`formation/` holds two different roles together: Conscript front and Flak support. Support first receives one hold-position move; only joint observed front arrival and support hold release its advance to the rear goal. Both roles must have simultaneous raw positions with correct ordered spacing. SDK move count is fixed at3; ordinary AI return applies to both. `client.py` exports `TacticalExecutor(session_path, natural_observation_path, commander_id)` with `start`, `update_context`, `grant_capability`, `submit`, `status`, `manifest`, and `stop`. Import/start do not inject. `update_context` accepts trusted own formation rosters/version/role, known region XYZ+observed_frame, public currently visible contacts, and a current session visibility proof path. Model tasks use abstract formation/contact IDs. The class resolves own units and starts native work only in its serial worker. Explicit developer-only calibration methods are `submit_move_probe`, `submit_attack_probe`, and `submit_formation_probe`.

Normal `submit` routes only purposes whose raw evidence passed `evidence.py`: attack.main_attack, raid.harass_economy (separate economy-target evidence), combined_arms.coordinate_force. Recon is being integrated separately with new-clear-cell evidence. All capabilities default to empty. Source report/EXE/package/commander/player/tool revisions are checked, and raw event assessments are recomputed rather than trusting a saved success status.

Receipts distinguish queued, dispatching, actual started, completed, failed and unknown. They expose frozen expiry, true issued frame, formation_versions, command source, observed interference, goal result and restoration. Unknown dispatch retains the unit reservation. Child reports must match command/task/sequence/session/ObjectIDs, have a zero host exit, and complete their restore chain. Existing command report paths require recovery; they are never overwritten by a retry.

The manifest accepts requested force_fraction .01..1, uses min(request,.5) internally, floors an eligible own-force budget, and records requested/capped/allocated fractions. A zero budget blocks; the two-role task requires at least two units. Task expiry requires 300..900 remaining logical frames (15fps). The host can advertise these limits to the model.

All tactical components hook overlapping native functions and must be globally serialized by the orchestrator. The preceding component must be terminal, have every entry restored, and have active callbacks0 before another is installed. Native timers retain safe return capability when a host process exits; paused/hung return remains pending and never counts as restored. Do not start a new lease while a prior outcome is unknown.

JSON reports use bounded Windows sharing-violation retries (25 attempts,20ms). Tests cover transient/permanent rename locks while preserving prior evidence, raw geometry/time/target counterexamples, command/version/expiry/visibility boundaries, and unknown restoration handling.

## Bounded ordered AK attack and actor disposal

`ordered-attack/` follows normal Script Stop → three clean distinct logical frames → one ScriptAttack order (INT_MAX native burst, source1) → Stop → normal native pool return. It does not claim a one-bullet limit. Immutable `ordered-ak03-static.json` in run20261025-010403 captured actor787's AK damage against WarFactory822, HP2775→2770 atframe2716, followed by timer-observed ammo3→2 at2717 and return2722. `ordered_qualification.py` joins the actual Body-call DamageInfo argument, exact source/target/AK asset, matching HP commit, near-tick same-entry ammo chain, ordered Stop/Attack/damage/return events, FOV guards and2047 restored/active0. Independent qualification grants only `attack.main_attack` for Conscript AK against verified ground target roles. It preserves the old diagnostic assessment and report. Harassment requires a separate successful exact SovietRefinery economy case; relabeling a structure cannot grant it.

Current AK mode is read through the verified slot getter mirror before model dispatch. Initial ammo1..3 is allowed only when the raw drop chain starts at that count, remains continuous and ends at the native final count. Molotov, aircraft targets, unknown templates and empty clips are blocked by this approved scope.

`readonly_disposal.py` is a separate, read-only failed-task cleanup path for an ordered actor lost before return. It checks the original report hash, owned process/session/start, loaded DLL hash and pinned timer/shared-pointer offsets, actual timer0, callbacks0, all11 exact restored executable entry signatures and native request identity. Two complete live-list scans must each fit one logical frame, advance between scans and both omit the original actor ID. It records an immutable `.disposal.json` sidecar; `verify_path(sidecar,original_report)` independently rechecks it. Success means exclusive bridge control is safely released; `return_verified`, `goal_observed` and task completion remain false. Unknown identity, an actor still in the live list, paused/nonadvancing frames or incomplete restoration keeps the lease quarantined. The client waits up to12seconds before deciding. This branch has offline counterexample coverage and still requires a live in-lease casualty validation before claiming field verification.
