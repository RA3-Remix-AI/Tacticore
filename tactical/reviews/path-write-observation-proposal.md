## Alternative: exact DWORD write watch

If setter coverage cannot be proven, an external hardware data breakpoint could observe the exact owned actor's aligned AIUpdate+150 DWORD. It must be a new diagnostic tool, with no command/API side effect. Preflight must bind PID and process start/session, current live ThingID/owner/type/update back-reference and frame; refuse an existing debugger, any existing debug-register use, or ambiguous thread identity. Save complete original thread contexts including DR0-DR3/DR6/DR7 and EFLAGS before changing one free local watch slot. Watch a 4-byte write only. Do not alter the path value or skip the triggering instruction.

Coverage cannot silently assume that only the simulation thread writes. Either establish the writer thread statically, or arm each existing game thread and account for new-thread debug events before resuming it. On a matching single-step exception, capture actual post-write EIP, registers, raw stack, watched DWORD, old value from the last captured snapshot, identity/frame/own state data and code bytes. Windows data breakpoints report after the instruction: identify the actual writer instruction from verified EXE instruction boundaries, not by subtracting a fixed byte count. Do not claim the first captured write's prior value if no preceding snapshot exists.

Use a small hard cap (for example16 matching writes) and a wall deadline. Restore every touched debug register and other changed context field exactly, detach the debugger without killing the game, and independently re-read the restored debug-register state before claiming observer release. Preserve unrelated exception semantics: only consume a matching own hardware watch exception; other exceptions remain for the original handler. Process/thread exit is a distinct terminal condition and does not prove native actor Return. Any inability to restore or account for a new thread is an explicit diagnostic failure. No machine-wide registry, mitigation, driver, security, or debugger configuration change is allowed.

This option is more intrusive than a verified passive setter observer and can perturb timing. It is not proposed for the current vanished804/806 addresses and should not be installed until Root selects the concrete observation plan and a fresh bounded diagnostic actor/window.
