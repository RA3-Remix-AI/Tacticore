## 确定的系统职责

模型战略层维护一个有持续性的计划：经济/科技/生产/防守预算方向、兵种职责配比、扩张条件、进攻窗口、侦察重点、撤退原则。性格影响风险容忍度和战术偏好，游戏规则始终由本地模块校验。先输出有限的策略选项和数值范围，再逐步增加自由度。

本地执行层校验资源、供电、科技前置、阵营与建造空间，按照模型意图维护生产队列，管理小队任务。原生AI保留可验证且不冲突的执行能力；不能假设它会自动理解策略JSON。需要找到可用的原生AI战略状态/生产权重切换接口，或者在原生AI之外实现相应执行器。原生小队微操与外部任务的分工仍需验证，已有移动调用不等于已接管小队。

游戏桥接只接收经过校验的有限命令，提供可见敌情、己方资源、科技、生产状态、小队状态和任务结果。模型不直接执行任意Lua、内存写入或地址调用。SDK定义的Mod资产资料作为本地权威知识来源。

建议模型策略契约示例（设计草案，尚无执行器）：

```json
{
  "snapshot_id": 184,
  "valid_for_game_seconds": 20,
  "stance": "pressure",
  "production_focus": "anti_air",
  "economy_policy": "expand_if_defensible",
  "tech_policy": "hold_current_tier",
  "reserve_fraction": 0.25,
  "objective_region": "north_expansion"
}
```

字段只能选择本地注册的枚举与区域ID；没有合法选项则拒绝。快照编号和游戏时间用于丢弃过时计划。预算、生产和攻防意图应保持稳定，重大事件触发重新判断，普通更新不能反复取消现有任务。

## 下一阶段验收

1. 探索原生AI战略状态、生产和小队控制接口；确认模拟线程及命令来源。
2. 打通一个有可观测结果的建造方向切换，例如对比基线后优先补防空；必须检查真实生产队列、花费和出厂单位。
3. 实现结构化局势、模型策略校验、超时本地接续与计划日志。
4. 桌面端增加目标电脑玩家、开始/停止指挥、当前计划和执行反馈；接管能力通过后再启用。
5. 多场固定地图对比预设性格：统计无效命令、策略变更频率、生产和任务完成率，再测玩家能否辨认不同打法。胜率不是唯一目标。

当前不承诺具体工期；最关键的不确定项是原生AI控制权和生产接口，而不是模型端点本身。
